## §2. Известные скиллы (преднастроенные интеграции)

Для каждого скилла, который уже встречался в проекте — записано
поведение **после интеграции**. Если скилл здесь есть — действуй
по этой записи, не разбирайся заново.

### `/fewer-permission-prompts`
- **Дефолт**: пишет в `.claude/settings.json` (project-level).
- **Интеграция**: писать в `.claude/settings.local.json`.
- **Слияние**: добавлять записи в `permissions.allow`, не пересоздавать файл.
- **Прецедент**: коммит `650c906` (2026-05-06).

### `/init`
- **Дефолт**: создаёт корневой `CLAUDE.md`.
- **Интеграция**: у проекта уже есть `CLAUDE.md` (Конституция). **НЕ ЗАПУСКАТЬ**
  без явного согласия Шамиля. Если запуск нужен — направить вывод в
  `docs/` под отдельным именем, не в корневой `CLAUDE.md`.

### `/security-review`
- **Дефолт**: выводит отчёт в чат.
- **Интеграция**: если найдены проблемы — каждая в `status/ISSUES.md`
  отдельной записью с типом `[security]`. Сводка — в `status/PROGRESS.md`.

### `/review`
- **Дефолт**: облачное многоагентное ревью PR.
- **Интеграция**: запускается явно Шамилем, не автоматически. Найденные
  баги — в `status/ISSUES.md` с типом `[review]`.

### `/simplify`
- **Дефолт**: правит код в diff'е.
- **Интеграция**: правки в `src/lisp/...` напрямую. Архитектурные
  изменения, если возникнут — отдельный ADR в `docs/decisions/`.

### `/update-config`
- **Дефолт**: пишет в `.claude/settings.json`.
- **Интеграция**: пишет в `.claude/settings.local.json` (как у `/fewer-permission-prompts`).

### `/session-start-hook`
- **Дефолт**: создаёт `.claude/hooks/session-start.sh` и регистрирует
  в `.claude/settings.json`.
- **Интеграция**: скрипт ОК как есть (`.claude/hooks/session-start.sh`),
  регистрация — в `.claude/settings.local.json`.

### `/claude-api`
- **Не применимо** к этому проекту (мы не строим Claude API приложение,
  а пишем AutoLISP). Если приложение всё-таки появится — добавить новую
  директорию `tools/` и записать новые правила.

### `/keybindings-help`
- **Не применимо** к проекту, только к личным настройкам Шамиля.
- **Интеграция**: правки только в `~/.claude/keybindings.json`,
  не трогать репозиторий.

### `/loop`
- **Не записывает файлы** — только запускает команды по расписанию.
- **Интеграция**: нет правил, безопасен.

### `/caveman`
- **Дефолт**: не пишет файлы — только меняет стиль ответов.
- **Интеграция**: нет конфликтов с проектной структурой.
- **Установлен**: `.claude/skills/caveman/SKILL.md`
- **Прецедент**: интегрирован через режим B skill-integrator (2026-05-06).

### `/skill-integrator` (этот скилл)
- **Дефолт**: пишет в `.claude/skills/skill-integrator/`.
- **Интеграция**: всё уже в нужном месте. Не трогать `SKILL.md`
  без явного запроса (там универсальный фреймворк).

## §3. Жёсткие правила проекта (что НЕ трогать)

- **`CLAUDE.md`** — Конституция. Изменения только с явного согласия Шамиля.
- **`docs/decisions/`** — ADR неизменяемы после принятия. Новое решение —
  новый ADR, старый помечается `superseded by NNNN`.
- **`samples/`** — реальные данные тахеометра. Не редактировать,
  не нормализовать, не "очищать". Только добавлять новые с датой в имени.
- **`src/lisp/commands/sv.lsp`** — основной файл команды SV. Правки только
  по согласованной спеке (`specs/001-*.md` или `002-*.md`), с журналом
  ревизий внутри спеки.
- **`~/.claude/settings.json`** — глобальные настройки Шамиля. Не трогать
  без явного запроса.

## §4. Журнал прецедентов (append-only)

Каждое нетривиальное решение по интеграции — отдельная запись.
Записи **никогда не удаляются**. Если решение пересмотрено —
новая запись с пометкой "supersedes <дата>".

### 2026-05-06 — Интеграция `/caveman` (режим B)
- **Контекст**: пользователь попросил сэкономить токены. Найден популярный
  скилл caveman (~55k звёзд). Интегрирован через режим B: SKILL.md
  адаптирован под проект (русский язык, ссылка на источник).
- **Решение**: `.claude/skills/caveman/SKILL.md`. Не пишет файлы проекта —
  конфликтов с картой нет. Добавлен в integration-map.md §2.
- **Ссылка в CLAUDE.md**: в таблице сценариев строка «Хочу сэкономить токены → /caveman».
- **Коммит**: следующий.

### 2026-05-06 — Диета CLAUDE.md (239 → 119 строк)
- **Контекст**: CLAUDE.md грузился в контекст каждой сессии целиком.
  При 239 строках это постоянная трата токенов даже для мелких правок.
- **Решение**: убраны полные чеклисты DoD/DoR (перенесены в `docs/workflow.md`
  с якорями `#dod` и `#dor`), убраны Handoff-протокол, Эскалация, KPI-детали.
  Вместо них — **таблица сценариев §4**: 12 строк "если X → иди туда".
  AI загружает детали только когда реально нужны (по сценарию).
- **Что осталось в CLAUDE.md**: ветка, проект, порядок чтения, Hard Rules,
  сценарная таблица, языковые конвенции, карта проекта, ритуал старта.
- **Коммит**: следующий.

### 2026-05-06 — Создание самого скилла `skill-integrator`
- **Контекст**: при первом запуске `/fewer-permission-prompts` стало
  очевидно, что скиллы по умолчанию плодят дубликаты файлов.
- **Решение**: создать проектный скилл-гейткипер.
- **Эволюция**: v1 был назван `skills`, объединял фреймворк и данные.
  v2 (текущая) — разделён на универсальный `SKILL.md` (готов к маркетплейсу)
  и проектный `integration-map.md` (этот файл).
- **Коммиты**: `990e0d3` (v1), `<следующий>` (v2 — рефакторинг).

### 2026-05-06 — `/fewer-permission-prompts`
- **Дефолт скилла**: писать в `.claude/settings.json` (project-level).
- **Решение**: направлено в `.claude/settings.local.json` (там уже был
  ручной allowlist Шамиля).
- **Что добавлено**: 6 GitHub MCP read-only инструментов
  (`list_commits`, `list_branches`, `list_pull_requests`, `list_issues`,
  `pull_request_read`, `issue_read`).
- **Итог**: один файл настроек проекта, никаких пересечений.
- **Коммит**: `650c906`.
