# SPEC-009: KG — картограмма земляных масс

**Статус**: черновик. Требования к оформлению и геометрии определены (§5, §5А); ждёт DWG для ведомости и умолчаний
**Дата создания**: 2026-09-01
**Автор**: AI-сессия (задача Шамиля)
**Файл реализации**: `src/lisp/commands/kg.lsp`
**Команды пользователя**: `KG` (рус. раскладка `ЛП`), `GC-CARTOGRAM`
**Связанные ADR**: [ADR-0005](../docs/decisions/0005-cartogram-own-math-cad-elevations.md), [ADR-0006](../docs/decisions/0006-dcl-dialog-generated-from-lisp.md), [ADR-0003](../docs/decisions/0003-standalone-command-files.md)
**Формулы**: [`docs/formulas.md` → Картограмма земляных масс](../docs/formulas.md#картограмма-земляных-масс)

---

## 1. Зачем

Картограмма земляных масс — обязательный чертёж при вертикальной планировке:
сколько грунта срезать, сколько досыпать, где проходит граница между этим.
Считать и чертить её руками долго и ошибкоёмко.

Требование Шамиля:

> «мне очень важно, чтобы квадраты строились, подписывались, объёмы и всё
> в этом духе как у Бердюгина, таблицы и так далее, то оформление как у него»

То есть **задан результат**, а способ его получить — на наше усмотрение.

---

## 2. Что делаем

Команда `KG` строит по площадке сетку квадратов, считает по каждому объёмы
выемки и насыпи, проводит линию нулевых работ, штрихует, подписывает
и сводит всё в ведомость.

### Откуда берутся числа

Решение зафиксировано в [ADR-0005](../docs/decisions/0005-cartogram-own-math-cad-elevations.md):

```
Civil 3D  →  отметка поверхности в точке XY     (единственное, что берём извне)
    ↓
наш LISP  →  рабочие отметки, объёмы, линия нулевых работ,
             ведомость, всё оформление
```

От Civil 3D нужна ровно одна операция — «дай отметку поверхности в точке XY».
Интерполяцию между точками съёмки он делает сам и делает правильно, это его
сильная сторона. Вся математика картограммы — наша, по открытым формулам,
каждую можно пересчитать на бумаге.

### Порядок работы команды

1. Выбрать **существующую** поверхность (чёрные отметки).
2. Выбрать **проектную** поверхность (красные отметки).
3. Задать **контур площадки** — замкнутая полилиния в чертеже.
4. Задать **сетку**: шаг, угол поворота, начало отсчёта.
5. Команда снимает отметки в узлах, считает рабочие, режет переходные
   квадраты линией нулевых работ, считает объёмы.
6. Рисует: сетку, подписи в узлах и квадратах, штриховки, линию нулевых работ.
7. Строит ведомость.

## 3. Вход

| Что | Откуда | Обязательно |
|---|---|---|
| Поверхность существующая | Civil 3D, выбор по имени | да |
| Поверхность проектная | Civil 3D, выбор по имени | да |
| Поверхность дополнительная | Civil 3D, третья — для этапности | нет |
| Пара для расчёта и её порядок | `Доп−Красная`, `Красная−Доп`, `Доп−Чёрная`, `Чёрная−Доп` | нет |
| Наружные границы | **замкнутые полилинии**, можно несколько — берётся общая область | нет |
| Внутренние границы | замкнутые полилинии, несколько — по ним области вырезаются | нет |
| Характерные линии | 2D/3D-полилинии и характерные линии Civil 3D — **режут квадраты на части** | нет |
| Шаг сетки **вдоль X** | ввод, шаблон между запусками | да |
| Шаг сетки **вдоль Y** | отдельно от X — сетка не обязана быть квадратной | да |
| Базовая точка сетки | указывается мышью | нет, по умолчанию угол габаритов |
| База отсчёта угла | `МСК` / `ПСК` / `Свой` | да, если угол не 0 |
| Угол поворота сетки | число либо указание на чертеже | нет, по умолчанию 0 |
| Обрезать краевые квадраты | тумблер | нет, по умолчанию обрезать |
| Высота текста | ввод, шаблон | нет, есть умолчание |
| Минимальный объём | порог подписи, по умолчанию `0,01 м³` | нет |
| Метод расчёта | по умолчанию по триангуляции | нет |
| Десятичный разделитель | точка или запятая | нет |

Отметки читаются **в МСК** (`docs/pitfalls.md` → П1). Контур, указанный мышью,
переводится в МСК на входе.

## 5. Модель оформления

Перечень того, что картограмма обязана уметь. Это **требования**, а не код:
какие объекты рисуются и какими свойствами управляются.

### 5.1. Объекты чертежа и их свойства

Девять объектов, у каждого **свой слой, цвет, тип линий, вес, прозрачность**:

| Объект | Что это |
|---|---|
| `Grid` | сетка квадратов |
| `Boundary` | граница площадки |
| `Mark` | подписи отметок в узлах |
| `Volume` | подписи объёмов в квадратах |
| `HatchPlus` | штриховка насыпи (`+`) |
| `HatchMinus` | штриховка выемки (`−`) |
| `HatchZero` | штриховка нулевой зоны |
| `ZeroLine` | линия нулевых работ |
| `Tabl` | ведомость |

Набор свойств у всех одинаковый — значит в коде это одна структура, а не
девять разных. Настройки импортируются и экспортируются файлом: у Шамиля
несколько объектов, оформление между ними переносится.

### 5.2. Сетка

| Параметр | Замечание |
|---|---|
| Поверхность **чёрная** (было) | выбор из списка поверхностей чертежа |
| Поверхность **красная** (стало) | то же |
| Базовая точка | указывается мышью |
| Размер **по горизонтали** | задаётся отдельно |
| Размер **по вертикали** | **отдельно от горизонтали** — сетка не обязана быть квадратной |
| Угол поворота | тип угла из списка, число либо указание мышью |
| Граница наружная | выбор объекта |
| Границы внутренние | выбор объектов — исключения, «дырки» в площадке |
| Характерные линии | выбор объектов |
| «Не обрезать квадраты» | тумблер: краевые квадраты либо режутся границей, либо остаются целыми |

**Три вещи, о которых легко забыть:** раздельный шаг по осям, внутренние
границы-исключения и тумблер обрезки краевых квадратов. Без них команда
разваливается на первом же нестандартном участке.

### 5.3. Подписи отметок в узлах

| Параметр | Значение |
|---|---|
| Стиль текста | из стилей чертежа |
| Точность | число знаков |
| Высота текста | число |
| Десятичный разделитель | выбор — запятая или точка |
| Цвет **красной** | отдельно |
| Цвет **чёрной** | отдельно |
| Цвет **рабочей** | отдельно |
| Скрывать задний план | тумблер — фон под текстом |
| Аннотативный | тумблер (у нас — с оглядкой на `docs/pitfalls.md` → П2) |
| Использовать существующий блок | тумблер |

**Ключевое решение: подпись узла — это блок с атрибутами, а не три
отдельных текста.**

Почему так:

- блок двигается и удаляется целиком, а не тремя кликами;
- атрибуты правятся списком, в том числе пакетно;
- оформление задаётся один раз в определении блока — поменял определение,
  перерисовались все узлы разом;
- готовый блок можно подставить свой: у Шамиля уже могут быть свои шаблоны.

Отсюда и та аккуратность, которой не бывает у россыпи текстов.

### 5.4. Объёмы, площади, таблица

| Параметр | Объём | Площадь | Таблица |
|---|:---:|:---:|:---:|
| Точность | + | + | + |
| Высота текста | + | + | + |
| Цвет | **три: `+`, `−`, `0`** | один | один |

Дополнительно:

- **минимальный объём** — порог, ниже которого квадрат не подписывается,
  чтобы чертёж не рябил нулями;
- **общая площадь** — выводится отдельно;
- **подписать инфо о поверхностях** — тумблер;
- **выбор метода расчёта** — методов несколько, и пользователь должен
  понимать разницу. Наш выбор обоснован в
  [ADR-0005](../docs/decisions/0005-cartogram-own-math-cad-elevations.md).

### 5.5. Линия нулевых работ

Тип линии, вес, цвет, масштаб типа линий. Отдельные тумблеры **Выемка /
Насыпь / Нулевая** — каждая со своим образцом штриховки и цветом,
и любую можно выключить.

### 5.6. Что ещё не определено

| Не определено | Как определим |
|---|---|
| **Колонки ведомости, заголовки, ширины** | из образца DWG |
| **Значения по умолчанию** — имена слоёв, цвета, высоты | из образца DWG |
| **Раскладка трёх отметок в узле** — порядок, стороны | из образца DWG, либо ставим стандартную и правим на первом прогоне |

Всё это снимается **из одного DWG с готовой картограммой**, причём
автоматически: слои, цвета, высоты текста, определение блока подписи
и структура таблицы читаются скриптом из файла. Разбирать руками ничего
не нужно.

## 5А. Геометрия: что обязано работать

Собрано из разбора задачи. Каждый пункт — то, обо что команда споткнётся,
если его не заложить сразу.

### 5А.1. Граница — любая кривая, не только полилиния

Контуром участка может быть `LWPOLYLINE`, `POLYLINE`, `LINE`, `ARC`, `CIRCLE`,
`ELLIPSE`, `SPLINE`. Ограничиваться полилинией нельзя: площадки с дугами
и скруглениями — обычное дело.

Отсюда способ резать сетку: **пересечение кривых**, а не разбор вершин
полилинии. В LISP это `IntersectWith` через ActiveX — работает с любым типом
кривой и возвращает все точки пересечения за один вызов.

**Пересечение сетки с границей — ядро всей команды.** Всё остальное
(площади, объёмы, штриховки) строится на его результате.

### 5А.2. Поворот — через систему координат, а не через каждую точку

Угол картограммы задаётся один раз, и дальше вся геометрия считается
в повёрнутой системе: строим сетку по осям, потом переводим. Поворачивать
каждую точку вручную — лишний источник ошибок.

Перекликается с [`docs/pitfalls.md` → П1](../docs/pitfalls.md#п1--пск-против-мск--самая-дорогая-ошибка):
работаем в МСК, перевод на границе.

### 5А.3. Границы бывают внутренние

Кроме наружного контура нужны **внутренние границы-исключения** — «дырки»
в площадке: существующие здания, колодцы, участки вне работ. Квадрат,
попавший на такую дырку, режется по ней.

### 5А.4. Характерные линии

Отдельный вход: линии перелома рельефа. Сетка обязана их учитывать, иначе
объём в квадрате с бровкой посчитается по прямой между углами и уедет.

### 5А.5. Копия поверхности вместо правки оригинала

Если для расчёта нужно навесить на поверхность границы — **работаем
с копией**, а оригинал не трогаем. Иначе после команды у пользователя
испорчена рабочая поверхность, и он даже не поймёт, кто это сделал.

### 5А.6. Порог минимального объёма

Квадраты с объёмом ниже порога не подписываются. Без этого чертёж рябит
нулями и десятыми долями кубометра, и его невозможно читать.

### 5А.7. Проверки входа — вслух

Краевые случаи, на которых команда обязана сказать внятно, а не упасть:

- контур не замкнут;
- выбран не тот тип объекта;
- поверхность не выбрана или их меньше двух;
- аргументов больше или меньше, чем нужно.

## 5Б. Не одна команда, а набор операций

**Ключевая поправка к архитектуре.** Мы задумывали `KG` как одну команду
с одним окном. Это неверно: работа делится на самостоятельные операции,
каждая со своей кнопкой, а окна открывают только три из них.

### 5Б.1. Карта операций

| Операция | Что делает | Окно | Наше имя |
|---|---|:---:|---|
| **Создать сетку** | поверхности, шаг, угол, границы | да | `KGC` |
| Создать сетку вдоль трассы | то же, но по оси и пикетажу | да | `KGT`, §11 |
| **Подписать отметки** | чёрная, красная, рабочая в узлах | да | `KGE` |
| Обновить отметки | пересчитать по изменившимся поверхностям | нет | `KGU` |
| Добавить отметку | вставить подпись в произвольном месте | нет | `KGA` |
| Проредить отметки | убрать подписи с вершин, не общих для соседних участков | нет | `KGW` |
| Обнулить рабочую | сделать рабочую = 0, оставив красную **или** чёрную | нет | `KGZ` |
| Удалить все отметки | только подписи, сетка остаётся | нет | `KGDE` |
| **Рассчитать объём** | объёмы, штриховки, подписи, ведомость | да | `KGV` |
| Удалить объёмы | только вычисления; сетка и отметки остаются | нет | `KGDV` |
| Объединить участки | свести мелкие регионы с соседними | нет | `KGM` |
| Выноска подписи | перенести подпись, оставив выноску от исходного места | нет | `KGB` |
| Настройка слоёв | слои, цвета, типы линий, веса | да | `KGL` |
| Удалить картограмму | целиком | нет | `KGDA` |

Имена — предложение, обсуждаемо. Каждой нужен кириллический двойник
(`docs/pitfalls.md` → П15).

### 5Б.2. Почему это лучше монолита

1. **Пересчёт без перестроения.** Поменялась проектная поверхность — жмём
   «обновить отметки». Сетку, границы и настройки не трогаем.
2. **Удаление послойное.** «Удалить объёмы» оставляет сетку и отметки —
   можно поправить отметки руками и пересчитать. В монолите пришлось бы
   начинать заново.
3. **Ошибка видна раньше.** Кривая сетка заметна до расчёта объёмов.
4. **Ручная доводка возможна.** Между шагами человек вмешивается: объединяет
   мелкие участки, прореживает лишние подписи, обнуляет рабочую там, где
   это нужно по проекту. Монолит такого не даёт вовсе.
5. **Окна не разрастаются** — П23 соблюдается сам собой.

Пункт 4 — самый важный и неочевидный. **Картограмма не считается одной
кнопкой**, между расчётом и оформлением всегда есть ручная правка.

### 5Б.3. Три поверхности, а не две

Поверхностей **три**: чёрная, красная и **дополнительная**. Считать можно
любую пару и в любом порядке:

```
Доп − Красная      Красная − Доп
Доп − Чёрная       Чёрная − Доп
```

**Порядок важен**: он задаёт знак рабочей отметки, то есть где выемка,
а где насыпь. Это не «лишняя настройка», а защита от зеркальной картограммы.

Зачем третья: этапность. Существующий рельеф, отметка после снятия
растительного слоя, проектная планировка — и объёмы нужны между разными
парами.

### 5Б.4. Угол поворота: МСК / ПСК / Свой

Не число, а **число плюс база отсчёта**:

| Вариант | Что значит |
|---|---|
| `МСК` | сетка параллельна осям мировой системы |
| `ПСК` | сетка параллельна осям текущей пользовательской системы |
| `Свой` | сетка повёрнута на введённый угол |

Ровно та развилка, на которой мы уже обжигались
(`docs/pitfalls.md` → П1). Молча выбрать одно из трёх нельзя.

### 5Б.5. Что уточнилось по каждому окну

**Сетка.** Наружных границ можно указать **несколько** — берётся **общая
область** поверхностей и границ. Внутренних тоже несколько — по ним области
**вырезаются**. Наружная и внутренние принимают **только замкнутые
полилинии**.

**Характерные линии не просто учитываются — они РЕЖУТ квадраты.**
2D/3D-полилинии и характерные линии Civil 3D. Там, где линия пересекает
квадрат, квадрат делится ею на части, и объём считается по частям.
Это не оформление, это геометрия расчёта.

**Отметки.** Цветов **шесть**, а не три: `Красная`, `Чёрная`, `Дополн.`
и **три отдельных для рабочей** — `Рабочая −`, `Рабочая 0`, `Рабочая +`.
Знак рабочей виден цветом, без чтения самого числа. Плюс десятичный
разделитель (точка или запятая), точность, высота, тумблеры «скрывать
задний план» и «аннотативный».

**Объёмы.** Точность, цвет и высота задаются **раздельно** для объёма,
площади и таблицы. У объёма три цвета по знаку (`+`, `−`, `0`). Порог
минимального объёма по умолчанию `0,01 м³`. Общая площадь размещается
выбором из списка (например «под таблицей»). Есть выбор **метода расчёта**
(стандартный — по триангуляции) и кнопка «в чём разница».

**Линия нулевых работ.** Тип линии, вес, цвет, масштаб типа линий.
Штриховки выемки, насыпи и нулевой зоны включаются отдельно, у каждой свой
образец (в эталоне `ANSI31`).

### 5Б.6. Блоки-шаблоны

Подписи ставятся блоками, и это **две разные штуки**:

| Блок | Что подписывает |
|---|---|
| `GC-Картограмма-Отметка` | три отметки в узле сетки |
| `GC-Картограмма-Объём` | объём и площадь в квадрате |

Оба создаются командой при первом запуске. Дальше их можно **править
в редакторе блоков** и включить «использовать существующий блок» — тогда
команда берёт готовый, а не пересоздаёт. Это и есть тот механизм, за счёт
которого оформление настраивается без программиста.

### 5Б.7. Мелочи, которые заметны только в работе

- **Картограмма именованная**: «План земляных масс №1». В чертеже их
  несколько, команды спрашивают, с какой работать.
- **Объединение подсвечивает мелочь**: участки меньше 2 % от базовой площади
  красным, меньше 25 % синим. Человек видит, что объединять.
- **Выноска**: подпись следует за курсором, левая кнопка фиксирует,
  правая удаляет.
- **Поля гаснут**, пока не выбраны поверхности — П23 в чужом исполнении.
- **Версия видна в углу окна** — при разборе «не работает» сразу понятно,
  о каком поведении речь. Возьмём себе.

### 5Б.8. Что из этого надо поправить в нашем окне

| Сейчас у нас | Должно быть |
|---|---|
| две поверхности | три плюс выбор пары и порядка |
| один цвет рабочей | три: `−`, `0`, `+` |
| угол числом | `МСК` / `ПСК` / `Свой` |
| нет десятичного разделителя | точка или запятая |
| порог объёма `0` | `0,01 м³` |
| нет выбора метода расчёта | есть, с пояснением |
| одно окно на всё | три окна по операциям |

Первые пять — мелкие правки. Последняя — разбиение, оно же §5Б.1.

## 6. Сценарий использования

Команда открывает **окно настроек**, а не ведёт по цепочке вопросов.
Обоснование — [ADR-0006](../docs/decisions/0006-dcl-dialog-generated-from-lisp.md):
у картограммы около тридцати параметров, через командную строку они
нечитаемы.

```
Команда: KG
  ┌─ Картограмма земляных масс ──────────────────────────────┐
  │ ┌ Поверхности ───────────────────────────────────────┐   │
  │ │ Чёрная (существующая)   [ Рельеф_сущ        ▼ ]    │   │
  │ │ Красная (проектная)     [ Планировка        ▼ ]    │   │
  │ ├ Сетка ──────────┬ Границы участка ──────────────┐  │   │
  │ │ Шаг вдоль X  20 │ Наружная        [ Выбрать ]   │  │   │
  │ │ Шаг вдоль Y  20 │ Внутренние      [ Выбрать ]   │  │   │
  │ │ Угол   0 [Указ.]│ Хар. линии      [ Выбрать ]   │  │   │
  │ │ Базовая [Указ.] │                               │  │   │
  │ │ [x] Обрезать краевые квадраты границей          │  │   │
  │ ├ Подписи отметок в узлах ────────────────────────┤  │   │
  │ │ Стиль [МГС ▼]  Высота 0,5  Точность [0,00 ▼]    │  │   │
  │ │ Цвет: чёрной ■  красной ■  рабочей ■            │  │   │
  │ ├ Объёмы ─────────────────────────────────────────┤  │   │
  │ │ Высота 0,5  Точность [0,0 ▼]                    │  │   │
  │ │ [ ] Не подписывать объём меньше [   ] м³        │  │   │
  │ │ Цвет: насыпь + ■  выемка − ■  ноль ■            │  │   │
  │ └─────────────────────────────────────────────────┘  │   │
  │                    [ OK ]  [ Отмена ]                    │
  └──────────────────────────────────────────────────────────┘
```

Правила из `docs/pitfalls.md` → П23 остаются, но в форме окна:

| Правило | Как в окне |
|---|---|
| Один главный режим, остальное подчинено | Неприменимое поле **гасится**, а не молчит |
| Никаких слепых переключателей | Всё видно разом, значение написано рядом с полем |
| Enter говорит вслух | `Отмена` не меняет ничего, `ОК` печатает принятое в консоль |

Плюс: **ошибка не закрывает окно.** Неверное значение подсвечивается строкой
внутри диалога, введённое не теряется.

Указание объектов и точек идёт **вне окна**: DCL не умеет тыкать по чертежу,
пока окно открыто. Окно закрывается, выбор делается, окно открывается заново
с сохранёнными значениями — поэтому перед каждым «Указать» поля вычитываются.

## 7. Edge-cases

| Случай | Поведение |
|---|---|
| Поверхность не выбрана | Внятное сообщение, повтор запроса |
| Visual LISP COM недоступен | Сообщить прямо: без него отметки с поверхности не прочитать (П6) |
| Контур не замкнут | Для границ участка нужна **замкнутая** полилиния: сказать вслух и переспросить |
| Несколько наружных границ | Берём общую область, а не первую попавшуюся |
| Характерная линия пересекает квадрат | Квадрат делится ею на части, объём по частям |
| Порядок пары поверхностей перепутан | Знак рабочей зеркальный — показываем выбранную пару в отчёте, чтобы это было видно |
| Контур — не кривая (текст, блок) | Внятное сообщение, повтор запроса |
| Контур — дуга, окружность, сплайн | Работать наравне с полилинией: режем пересечением кривых |
| Внутренняя граница вне наружной | Пропустить со счётчиком, сказать вслух |
| Объём квадрата ниже порога | Квадрат считается, но не подписывается |
| Поверхность нужно менять для расчёта | Работать с копией, оригинал не трогать |
| Узел сетки вне поверхности | Квадрат пропускается, счётчик пропущенных в отчёте |
| Квадрат частично за контуром | Режется контуром, объём считается по фактической части |
| Все четыре угла одного знака | Целый квадрат, общая формула |
| Один угол против трёх | Треугольник плюс пятиугольник |
| Два против двух | Две трапеции |
| **Диагональный случай** | Разбить диагональю на треугольники — молча пропустить нельзя |
| Рабочая отметка ровно 0 в узле | Узел лежит на линии нулевых работ, в обе стороны не считается |
| Шаг сетки слишком мелкий | Предупредить до построения: тысячи квадратов считаются долго |
| Слой выключен / заблокирован | Проверка при запуске, как в `OL` и `VO` (П5) |
| Повёрнутая ПСК | Учтена: вся математика в МСК (П1) |

## 8. Критерий приёмки

1. **Сумма площадей частей квадрата равна `a²`** — на каждом переходном
   квадрате.
2. Знак не перепутан: насыпь `+`, выемка `−`, проверяется на одном узле руками.
3. Целый квадрат, посчитанный как переходный при нулевой отметке в углу,
   даёт тот же объём, что по общей формуле.
4. Диагональный случай обработан, а не пропущен.
5. **Итоговые объёмы сошлись с эталонным расчётом на том же участке.**
6. Оформление совпадает с образцом: сетка, подписи, штриховки, ведомость.
7. Команда запускается и как `KG`, и в русской раскладке.

Пункт 5 — главный. Эталон — инструмент, которым Шамиль пользуется сейчас:
гоняем обе программы на одном участке и сверяем итог. Расходится — ищем
по квадратам, где именно.

## 9. Этапы

Одним махом такую фичу делать нельзя. После каждого этапа — ручной прогон.

Этапы совпадают с будущими командами (§5Б) — это не совпадение, а следствие:
делим по тем же границам, по которым работа делится в жизни.

| Этап | Будущая команда | Что даёт |
|---|---|---|
| **1. Окно настроек** ✅ | — | параметры собираются и запоминаются |
| **2. Сетка** | `Создать сетку` | сетка по границам, с углом и обрезкой |
| **3. Отметки в узлах** | `Подписать отметки` | чёрная, красная, рабочая блоком с атрибутами |
| **4. Объёмы целых квадратов** | `Рассчитать объём` | объёмы там, где знак не меняется, штриховки |
| **5. Линия нулевых работ** | там же | разрез переходных квадратов, площади, объёмы частей |
| **6. Ведомость** | там же | таблица с итогами и балансом |
| **7. Слои и доводка** | `Настройка слоёв` | оформление по образцу |

**Почему окно первым, а не последним.** Оно дешевле всего в правке и дороже
всего в переделке: расчёт, написанный под один набор параметров, потом
не переставишь. Шамиль смотрит окно, говорит что переименовать и переставить,
и только после этого под него пишется математика.

Этап 5 — основной риск. До него объёмы неполные, и команда говорит об этом
вслух в отчёте, чтобы промежуточный результат не приняли за готовый (R6).

## 10. Открытые вопросы

Блокирует только ведомость (этап 4), остальное можно делать уже сейчас:

1. **Образец DWG** с готовой картограммой — нужен для колонок ведомости,
   раскладки отметок в узле и значений по умолчанию (§5.6). Всё остальное
   уже определено.
2. **Поверхности Civil 3D**: они у Шамиля уже построены, или строятся
   под задачу? От этого зависит, нужен ли запасной путь с собственной
   интерполяцией по точкам съёмки.
3. **Контур площадки**: всегда есть готовая полилиния, или её надо
   указывать точками?
4. **Ведомость**: в модель рядом с сеткой или на лист? Одна на площадку
   или по участкам?
5. **Разрыхление**: коэффициент вводится или объёмы чисто геометрические?
   По умолчанию — геометрические, см. `docs/formulas.md`.

Не блокируют, решим по ходу:

- нумерация квадратов — как в образце;
- нужен ли режим «проектная отметка при нулевом балансе» (формула уже
  выписана в `docs/formulas.md`);
- нужен ли **режим для линейных объектов** — см. §11.

## 11. Линейный режим — на будущее

Для дорог и прочих линейных сооружений картограмма строится иначе: не по
габаритам площадки, а **вдоль трассы**.

| Вход | Замечание |
|---|---|
| Поверхность чёрная, поверхность красная | как в основном режиме |
| **Трасса (ось)** | дополнительный объект |
| **Пикетаж: начальный и конечный** | в формате «ПК + смещение» |
| Шаг сетки **вдоль оси** | отдельно |
| Шаг сетки **поперёк оси** | отдельно |

Сетка кладётся по трассе, а не по осям чертежа: ряды идут по пикетажу,
столбцы — поперечниками.

В `CLAUDE.md` дороги заявлены в области проекта, так что режим пригодится.
Сейчас **не в scope** — сначала площадочный вариант целиком. Записать
в `status/BACKLOG.md`.
