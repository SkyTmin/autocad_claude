**Дата создания**: 2026-05-03

**Дата ревизий**: 2026-05-03 (v2, v3 — журнал в §11)
**Автор**: AI-сессия #1 (по запросу Шамиля)
**Связанные ADR**: ADR-0001 (гибрид)
**Связанные спеки**: SPEC-001 (одиночная свая) — расширяем
**Реальный sample**: `samples/csv/2026-05-03-pile-sample-multi.csv` (106 точек, ~10 свай на разной глубине)

## 1. Зачем (Why)

После прогона SPEC-001 на одной свае Шамиль захотел обрабатывать **сразу
много свай** одной командой. На стройке причала обычно за день погружают
десятки свай — обрабатывать каждую отдельно нереалистично.

Цель: **выделить рамкой все точки многих свай → получить готовую графику
по каждой свае** одним вызовом команды.

## 2. Что делаем (What)

**Расширяем режим 1 команды `sv`** (не делаем отдельный режим). Старое
поведение для 1 сваи остаётся как частный случай (N=1 кластер). UI не меняется.

Алгоритм для режима 1 (**v3 — поиск сечений + группировка в сваи**):

```
все выделенные точки (без предварительной Z-кластеризации)
    │
    ▼ ЖАДНЫЙ ПОИСК СЕЧЕНИЙ
    │  пока есть ≥3 точек:
    │   1. перебор C(N,3) троек, среди которых
    │      Z-разброс ≤ 50 мм (точки одного сечения)
    │   2. среди них — окружность с
    │      |R−710| ≤ 50 мм и min |R−710|
    │   3. все точки в радиусе R+ε от центра
    │      И на том же Z (±50 мм) — точки сечения
    │   4. удалить их из массива, повторять
    │
СПИСОК всех сечений: ((center, z, points) ...)
    │
    ▼ ГРУППИРОВКА В СВАИ
    │   - сечения с XY-центрами в пределах 0.5 м — одна свая
    │   - в свае 2+ сечений: min Z = нижнее, max Z = верхнее
    │   - dZ должно быть в [0.3 м; 5 м]
    │
для каждой сваи: существующая SV-логика (SPEC-001):
- окружность (красный/зелёный)
- стрелки от центра нижнего, длиной 400 мм
- подписи (одно целое число мм/1м) рядом со стрелкой в нужном квадранте
```

**Ключевое отличие v3 от v2**: НЕТ глобальной Z-кластеризации в начале.
В реальной съёмке Шамиля сваи погружены на РАЗНУЮ глубину — нижние сечения
разных свай на разных Z (0.5, 0.98, 1.40, 1.98...). v2 брал «2 самые большие
группы по Z», предполагая что это «низы всех» и «верхи всех» — это допущение
неверно для свай разной длины. v3 ищет каждое сечение индивидуально через
плановую окружность с фильтром по Z-однородности тройки.

## 3. Вход

- Точки уже импортированы в Civil 3D, поддерживаемые типы — те же, что
  в SPEC-001 v3 (`POINT`, `AECC*POINT`, `AEC*POINT`).
- Пользователь выделяет рамкой **все** точки всех свай разом.
- Минимум 6 точек на сваю (3 низ + 3 верх).
- Минимум 1 свая, максимум — без ограничения.

## 4. Выход

Для **каждой** обнаруженной сваи команда добавляет в чертёж тот же
комплект объектов, что и SPEC-001:
- Красная окружность низа (`GC-Сваи-Низ`)
- Зелёная окружность верха (`GC-Сваи-Верх`)
- Две стрелки от центра нижнего, длина 400 мм (`GC-Сваи-Отклонения`)
- Две подписи — одно целое число мм/1м, **в 4 квадранта круга** по таблице
  (см. ниже)
- В консоль — сводка по каждой свае (нумерация в выводе только для удобства,
  на чертеже свая не подписывается).

### Положение подписей (v2)

Делим круг на 4 части (квадранты):
- 1 = верх-право, 2 = верх-лево, 3 = низ-лево, 4 = низ-право.

| Знак dx | Знак dy | Y-стрелка → подпись в части | X-стрелка → подпись в части |
|---|---|---|---|
| + | + | 1 (верх-право) | 4 (низ-право) |
| − | + | 2 (верх-лево) | 3 (низ-лево) |
| + | − | 3 (низ-лево) | 2 (верх-лево) |
| − | − | 4 (низ-право) | 1 (верх-право) |

Y-подпись повёрнута на 90° (читается снизу вверх), X-подпись — без
поворота.

**v3** — формула: пусть `sx=sign(dx)`, `sy=sign(dy)`, `sxy=sx·sy`. Тогда:
- Y-текст: `(cx + sxy·lateral, cy + sy·along)`
- X-текст: `(cx + sx·along,    cy − sy·lateral)`

Где:
- `along = *gc-pile-text-along*` ≈ 0.20 м — смещение ВДОЛЬ стрелки от центра
- `lateral = *gc-pile-text-lateral*` ≈ 0.10 м — смещение ПЕРПЕНДИКУЛЯРНО

Это размещает подпись **рядом со стрелкой** (середина) в нужном квадранте,
а не далеко в углу четверти круга (как было в v2). Текст хорошо виден,
не наезжает на саму стрелку и не теряется на фоне круга.

## 5. Сценарий использования

1. Шамиль импортировал точки многих свай в Civil 3D.
2. `(load "...sv.lsp")` (один раз).
3. `SV` → `1` → выделить рамкой **все точки всех свай** → Enter.
4. Команда:
   - Кластеризует, находит N свай.
   - Печатает: `[i] Найдено свай: N. Обрабатываю...`
   - Для каждой сваи — отдельная сводка в консоли:
     ```
     --- Свая 1 / N ---
     Низ:  ... R = ...
     Верх: ... R = ...
     dX = ... dY = ...
     ```
   - Рисует объекты для всех свай за один проход.
5. В конце: `[i] Обработано свай: N (пропущено: M)`, если что-то пропустилось.

## 6. Edge-cases

| Случай | Поведение |
|---|---|
| Найдена 1 свая (N=1) | Работает как SPEC-001 v3 (один цикл). |
| В выборке вообще нет 2 групп точек по Z (всё на одной высоте) | Ошибка: «Не найдено двух высотных уровней — это не свайные сечения». |
| Нижних кластеров больше, чем верхних (или наоборот) | Сопоставляем сколько можем; лишние пропускаем с предупреждением «свая X не имеет соответствующего верхнего/нижнего сечения». |
| Для нижнего кластера нет верхнего ближе чем 0.5 м | Эта свая пропускается, в консоль: «свая в районе (X,Y) — пара не найдена». |
| Сваи слишком близко (<1.0 м между центрами в плане) | XY-кластеризация склеит → одна общая группа с большим количеством точек. Алгоритм предупредит и попытается обработать; если радиус найденной окружности сильно больше 0.71 — предупреждение «возможно слипшиеся сваи». |
| В одном XY-кластере оказалось < 3 точек | Эта (потенциальная) свая пропускается. |
| Лишние точки/маркеры в выборке | Уже отфильтрованы на уровне `ssget` (SPEC-001 v3). |

## 7. Не в scope (MVP)

- **Нумерация / подписи свай** в чертеже (Шамиль явно сказал: без подписи).
  Идентификация в консольной сводке — только индекс по порядку обработки.
- **Сохранение результата в CSV/таблицу** — на будущее (Backlog).
- **Параметризация порогов** через prompt — пока константы в начале файла,
  Шамиль правит вручную (`*gc-pile-xy-cluster*`, `*gc-pile-pair-tolerance*`).
- **Civil 3D Point Groups** как источник входа — не используем, пользователь
  выделяет рамкой.
- **Сравнение с проектом** — то же не в scope, как в SPEC-001.

## 8. Критерий приёмки

Сценарий: импортировать в Civil 3D точки нескольких свай (например 2-3
сваи по 11 точек = 22-33 точки) → запустить `SV` → `1` → выделить рамкой все.

- [ ] В консоли выводится: «Найдено свай: N» (соответствует реальному количеству).
- [ ] Для каждой сваи появились красный круг низа, зелёный верха, 2 стрелки,
      2 подписи.
- [ ] Все объекты на правильных слоях (`GC-Сваи-*`).
- [ ] Геометрия каждой сваи соответствует SPEC-001 v3 §8.
- [ ] При работе с 1 сваей результат идентичен SPEC-001 v3.
- [ ] При сваях с расстоянием между центрами 1.5–2.5 м — не слипаются
      (правильная кластеризация).
- [ ] Edge-cases из §6 обрабатываются без падения команды.

## 11. Журнал ревизий

### v4 — 2026-05-07 (после прогона Шамиля: медленно + не находит сечения)

**Симптомы**:
1. При большой выборке (много свай) — очень долго думает.
2. Даже на одной свае: "найдено меньше 2 сечений с R 710".

**Root cause 1 — производительность**: `gc-pile-find-one-section` перебирал
C(N,3) по ВСЕМ точкам выборки. При 100 точках — 160 000 троек в AutoLISP
(каждая с `gc-pile-circle-3`). При 200 точках — 1 300 000 троек. Линейный
рост числа точек → кубический рост времени.

**Фикс**: Сортировка всех точек по Z + тройной CDR-цикл с ранним выходом.
Внутренние циклы j и k останавливаются как только Z[j]-Z[i] > z-cluster.
Для 100 точек в 10 группах по 10 → ~1 200 троек вместо 160 000 (~130×
быстрее). CDR-итерация вместо `nth` — O(1) на шаг без накладных расходов.

**Root cause 2 — диагностика**: при неудаче `gc-pile-find-one-section`
возвращал nil молча. Пользователь не мог понять: неверный диаметр сваи
в константе, неправильные Z-отметки или что-то ещё.

**Фикс**: отслеживаем `diag-r` — лучший найденный R независимо от допуска
`*gc-pile-fit-tol*`. При неудаче: печатаем найденный R и ожидаемый диапазон.
Пример: `[?] Лучший R: 355 мм (ищем 710 ±50 мм)` — сразу понятно что надо
поправить `*gc-pile-r-norm*` (свая Ø710 мм вместо Ø1420 мм).

В `gc-pile-mode1` при ошибке: показываем диаметр и Z-диапазон выборки.

**Удалены**: `gc-pile-z-spread`, `gc-pile-combos3` больше не нужны в
`gc-pile-find-one-section` (оба остались для `gc-pile-best-circle`).

**КОД НЕ ПРОВЕРЕН в Civil 3D — ждёт прогона у Шамиля.**

### v3 — 2026-05-03 (после прогона на реальном многосвайном sample)

**Что показал прогон v2**: на 3 сваях работало частично (на одной только
верхнее сечение, на другой ничего). На реальном sample (10+ свай на разной
глубине: Z от 0.5 до 4.0 м) большинство свай терялось.

**Root cause**: v2 делал глобальную Z-кластеризацию всех точек и брал
2 самые большие группы как «низы всех» / «верхи всех». Но на реальном
объекте сваи погружены на РАЗНУЮ глубину — нижние сечения разных свай
лежат на разных Z. Допущение «все низы на одном Z» неверно → часть свай
не попадает в эти 2 группы и игнорируется.

**Фикс v3 — поиск каждого сечения индивидуально**:
1. Глобальная Z-кластеризация удалена.
2. В жадном цикле перебираем C(N,3) троек по всему массиву; тройка валидна
   если её точки на одном Z (Δ ≤ 50 мм) И окружность по XY с R≈710 мм.
3. Все точки в радиусе R+ε от центра НА ТОМ ЖЕ Z = точки сечения.
4. Удаляем, повторяем — получаем список ВСЕХ сечений (нижних И верхних
   всех свай вперемежку).
5. Группируем сечения в сваи: сечения с XY-центрами в пределах 0.5 м =
   одна свая. В свае: min Z = нижнее, max Z = верхнее. dZ должно быть
   в [0.3 м; 5 м].

**Также — текст теперь РЯДОМ со стрелкой**, не в углу квадранта (фидбек
Шамиля «расположение хреново, надо рядом со стрелочкой»). Раньше offset
был 0.4 м, текст уезжал на угол круга. Теперь — along=0.2 м (вдоль стрелки)
+ lateral=0.1 м (вбок) = подпись на середине стрелки, в нужном квадранте.

Удалены устаревшие функции: `gc-pile-cluster-z`, `gc-pile-cluster-by-gap`,
`gc-pile-find-one-pile`, `gc-pile-find-all-piles`, `gc-pile-pair-piles`.
Добавлены: `gc-pile-z-spread`, `gc-pile-find-one-section`,
`gc-pile-find-all-sections`, `gc-pile-group-sections-into-piles`.

### v2 — 2026-05-03 (после первого прогона у Шамиля)

Скрины показали: при 3 сваях работает только частично — на одной рисуется
только верхнее сечение, на другой ничего, на третьей только красный.

**Root cause**: single-linkage XY-кластеризация (v1) склеивает соседние сваи.
При расстоянии между центрами 1.5–2.5 м точки разных свай в плане могут
быть ближе друг к другу (~0.1–0.5 м), чем точки одной сваи на крайних
концах дуги (до 1.4 м). Single-linkage соединит цепочкой две соседние сваи
в один большой кластер → меньше кластеров чем свай → часть свай не получает
ни нижнего, ни верхнего сечения.

**Фикс — поиск свай через окружность** (greedy circle-fit):
1. Z-кластеризация — без изменений.
2. В каждой Z-группе (нижние всех свай / верхние всех свай) — жадный цикл:
   - Перебираем все C(N,3) троек.
   - Берём окружность с min `|R − 710|` среди тех, у кого `|R − 710| ≤ 50 мм`.
   - Все точки в радиусе R+ε (ε=50 мм) от её центра — точки этой сваи.
   - Удаляем их, повторяем.
3. Сопоставление пар низ↔верх — без изменений (по близости центров ≤0.5 м).

**Также правки положения текста**: новые правила в 4 квадранта по знакам
`(sign(dx), sign(dy))` — см. §4. Реализация через формулу с `sxy = sx·sy`
покрывает все 4 случая. Заменили v3-правила (X→ под, Y↑ слева и т.п.) —
по фидбеку Шамиля те правила были неудобны для глаза в реальном чертеже.

### v1 — 2026-05-03 (первая версия)

Single-linkage XY-кластеризация (порог 1.0 м) + сопоставление пар.

## 12. Технические заметки

### Параметры по умолчанию (v3)

| Параметр | Значение | Где |
|---|---|---|
| Порог Z-однородности тройки/сечения | 0.050 м | `*gc-pile-z-cluster*` |
| Допуск \|R−710\| при поиске сечения | 0.050 м | `*gc-pile-fit-tol*` |
| Запас сверх R при сборе точек сечения (ε) | 0.050 м | `*gc-pile-fit-radius-eps*` |
| Допуск сопоставления XY-центров сечений сваи | 0.500 м | `*gc-pile-pair-tolerance*` |
| Минимальный dZ между сечениями одной сваи | 0.300 м | `*gc-pile-pair-dz-min*` (v3) |
| Максимальный dZ между сечениями одной сваи | 5.000 м | `*gc-pile-pair-dz-max*` (v3) |
| Смещение текста ВДОЛЬ стрелки | 0.200 м | `*gc-pile-text-along*` (v3) |
| Смещение текста ПЕРПЕНДИКУЛЯРНО стрелке | 0.100 м | `*gc-pile-text-lateral*` (v3) |

### Сложность

Greedy circle-fit: на каждой итерации `O(N³)`. Для N=50 точек — ~20k троек,
для AutoLISP это ~1-2 секунды. На больших полях (50+ свай → 250+ точек на
группу) может потребоваться оптимизация.

### Ложные срабатывания

Случайная тройка из 3 точек разных свай может дать R≈710 мм. Защита:
после нахождения окружности проверяем что в радиусе R+ε от её центра ≥ 3
точек. Если нет — отвергаем тройку. На практике три случайные точки разных
свай редко лежат на окружности с радиусом ровно 710 мм (требует совпадения
геометрии в узком допуске 50 мм).
