# SPEC-005: VID — выделение объектов рамкой заданного размера

**Статус**: реализовано в `vid.lsp v1`, нужен ручной прогон в Civil 3D
**Дата создания**: 2026-07-29
**Автор**: AI-сессия (задача Шамиля)
**Файл реализации**: `src/lisp/commands/vid.lsp`
**Команды пользователя**: `VID` (алиас), `GC-SELECT-BY-SIZE` (полное имя)
**Связанные ADR**: —

---

## 1. Зачем

Сейчас Шамиль выделяет объекты вручную, растягивая рамку мышью. Объектов много,
работа муторная и неточная: попасть рамкой в нужный размер на глаз нельзя,
а чуть промахнулся — захватил лишнее или потерял нужное.

`VID` заменяет ручное растягивание вводом точных размеров: указал угол, ввёл
длину и ширину — рамка построилась сама, объекты выделились.

## 2. Что делаем

Команда строит прямоугольную область выделения по указанной точке и двум
введённым размерам, затем выделяет объекты **строго внутри** этой области
(режим «синей» рамки AutoCAD — только полностью попавшие объекты).

Ключевые решения (согласованы с Шамилем 2026-07-29):

- **Точка привязки — левый верхний угол.** Рамка растёт вправо и вниз.
  Это соответствует формулировке «Y от верха экрана до низа, X от левого края
  к правому».
- **Запятая — обычный десятичный разделитель метров.** `5,300` = 5.300 м,
  `5,3` = 5.300 м, `5,05` = 5.050 м, `5,005` = 5.005 м. Точка `5.300`
  равнозначна запятой.
- **Тип выделения — только «синее» (window)**, `ssget "_W"`. Объект, который
  рамка лишь задела, не выделяется.

## 3. Вход

- Источник данных: ручной ввод в командной строке AutoCAD/Civil 3D.
- Файл-пример не требуется: команда не читает файлы, работает с текущим DWG.

### Пример входных данных

```
Команда: VID
Укажите левый верхний угол области выделения: <клик в модели>
Размер по Y (сверху вниз), м: 12,500
Размер по X (слева направо), м: 40,000
```

## 4. Выход

Набор объектов, выделенных с ручками (grips) — как если бы Шамиль выделил их
мышью. Выделение остаётся активным после завершения команды, поэтому сразу
можно нажать `Delete`, `Move`, `Copy` или задать свойства.

Никакой геометрии в чертёж команда не добавляет.

### Пример результата

```
[i] Рамка 40,000 × 12,500 м (X × Y), угол привязки — левый верхний.
[i] Область: X 1449070.000 … 1449110.000   Y 656400.000 … 656412.500
[i] Выделено объектов: 137
```

## 5. Сценарий использования

1. Загрузить `src/lisp/commands/vid.lsp` через `APPLOAD`.
2. Ввести команду `VID`.
3. Кликнуть точку — она станет левым верхним углом рамки.
4. Ввести размер по `Y` (сверху вниз), например `12,500`.
5. Ввести размер по `X` (слева направо), например `40,000`.
6. Объекты внутри области выделяются с ручками.

Повторный запуск предлагает прошлые размеры значениями по умолчанию — можно
просто нажать `Enter`, чтобы выделить такой же участок в другом месте.

## 6. Edge-cases

| Случай | Поведение |
|---|---|
| Esc при выборе точки | Команда завершается сообщением `[ОТМЕНА]`, ничего не выделяется |
| Пустой ввод размера, значения по умолчанию нет | Повтор запроса с примером `5,300` |
| Пустой ввод размера, значение по умолчанию есть | Берётся значение из прошлого запуска |
| Нечисловой ввод (`абв`, `5,3,7`, `--5`) | Повтор запроса с пояснением, команда не падает |
| Пробелы в размере (`5, 300`, ` 5,300 `) | Игнорируются, читается как `5,300`. Ввод берётся целой строкой (`getstring T`), поэтому обрыва на пробеле нет |
| Ноль или отрицательный размер | Отклоняется, повтор запроса: рамка нулевой площади бессмысленна |
| В области нет объектов | Сообщение `[i] В указанной области нет объектов…`, выделение не ставится |
| Объекты на замороженных/выключенных слоях | Не выделяются — штатное поведение AutoCAD, не баг |
| Объекты на заблокированных слоях | Выделяются, но изменить их AutoCAD не даст — штатное поведение |
| Объекты пересекают границу рамки | **Не** выделяются: режим `window`, а не `crossing` |
| Активен 3D-вид (не «сверху») | Рамка строится в плоскости текущей ПСК; в перспективе результат непредсказуем — работать в виде сверху |

## 7. Не в scope

- Фильтр по типу объектов (только линии, только точки и т.п.).
- Отрисовка прямоугольника рамки как объекта чертежа — команда не мусорит в DWG.
- Режим «зелёного» выделения (crossing) — по задаче нужен только «синий».
- Привязка к другим углам (левый нижний, центр) — выбран один, левый верхний.
- Поворот рамки под углом — рамка всегда по осям текущей ПСК.

## 8. Критерий приёмки

- [ ] Команда `VID` доступна после `(load "src/lisp/commands/vid.lsp")`
- [ ] Клик задаёт **левый верхний** угол; рамка уходит вправо и вниз
- [ ] `5,300` и `5.300` и `5,3` дают один результат — 5.300 м
- [ ] Объект, который рамка лишь задела, **не** выделяется
- [ ] После завершения команды объекты остаются выделенными с ручками
- [ ] Повторный запуск предлагает прошлые размеры по умолчанию
- [ ] Нечисловой ввод не роняет команду
- [ ] Esc на любом шаге не роняет команду и не оставляет мусор

## 9. Зависимости

- От других спек: нет. `VID` не связана с `SV`/`SVP`.
- От внешних библиотек: Visual LISP (`vl-string-subst`).
- От настроек Civil 3D: нет.
