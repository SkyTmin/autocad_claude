# SPEC-005: VID — выделение объектов рамкой заданного размера

**Статус**: реализовано в `vid.lsp v6`, нужен ручной прогон в Civil 3D
**Дата создания**: 2026-07-29
**Автор**: AI-сессия (задача Шамиля)
**Файл реализации**: `src/lisp/commands/vid.lsp`
**Команды пользователя**: `VID` (алиас), `GC-SELECT-BY-SIZE` (полное имя)
**Связанные ADR**: —

---

## 1. Зачем

Сейчас Шамиль выделяет объекты вручную, растягивая рамку мышью. Объектов много,
работа муторная и неточная: попасть рамкой в нужный размер на глаз нельзя,
а чуть промахнулся — захватил лишнее или потерял нужное.

`VID` заменяет ручное растягивание вводом точных размеров: указал угол, ввёл
длину и ширину — рамка построилась сама, объекты выделились.

## 2. Что делаем

Команда строит прямоугольную область выделения по указанной точке и двум
размерам из шаблона, затем выделяет попавшие в неё объекты.

Ключевые решения (согласованы с Шамилем 2026-07-29):

- **Точка привязки — левый верхний угол.** Рамка растёт вправо и вниз.
  Это соответствует формулировке «Y от верха экрана до низа, X от левого края
  к правому».
- **Запятая — обычный десятичный разделитель метров.** `5,300` = 5.300 м,
  `5,3` = 5.300 м, `5,05` = 5.050 м, `5,005` = 5.005 м. Точка `5.300`
  равнозначна запятой.
- **Размеры — шаблон.** Задаются один раз и живут между запусками.
  Дальше каждый вызов `VID` — один клик, без подтверждений.
- **Тип выделения переключается** в меню (`2` или `Т`): «синее» (только целиком
  попавшие) или «зелёное» (всё, чего рамка коснулась). По умолчанию синее.
  Выбор тоже часть шаблона.

### Ревизия v2 (2026-07-29, после первого прогона Шамиля)

Первый прогон выявил два дефекта:

1. **Выделялось 1–2 объекта вместо всех.** Шамиль задал полосу 40 м × 30 мм.
   В режиме «window» объект выделяется только если попал **целиком**, а в
   полосу шириной 30 мм не помещается почти ничего. Это не баг реализации,
   а следствие ограничения на тип выделения из v1.
   **Решение**: добавлен переключатель `[Тип]` синее/зелёное, плюс
   предупреждение перед выборкой, если рамка уже 100 мм, а тип синий.
2. **Рамка не учитывала повёрнутую ПСК.** `ssget "_W"` принимает два угла и
   строит по ним прямоугольник, который **не поворачивается** вместе с ПСК.
   Шамиль выравнивает чертёж поворотом ПСК, поэтому рамка уезжала.
   **Решение**: `"_W"` заменён на `"_WP"` / `"_CP"` — явный четырёхугольник
   из 4 углов, заданных в текущей ПСК. Такая рамка поворачивается вместе
   с чертежом.

Третьим пунктом v2 убрала обязательный ввод размеров при каждом запуске
(см. «Размеры — шаблон» выше).

### Ревизия v6 (2026-07-29) — кнопки вернулись

v5 убрала `initget` совсем — ошибка: только `initget` делает опции
кликабельными. Настоящая причина, почему набранная буква не срабатывала:
для кириллицы AutoCAD не распознаёт заглавную букву как сокращение и требует
слово целиком. Решение — регистрировать и слово, и букву:
`(initget "Размеры Р Тип Т")`. Работает клик, `Р` и `Размеры`.
`Enter` по-прежнему открывает запасное текстовое меню.

### Ревизия v5 (отменена) — ключевые слова `initget` убраны совсем

Прогон `vo.lsp` показал, что ключевые слова `initget` в установке Шамиля
не срабатывают: набранная буква не распознаётся как опция, запрос глотает её
и принимает следующий клик за указание точки. В `vid.lsp` опции `[Размеры/Тип]`
сломались бы ровно так же.

**Решение то же, что в `vo.lsp v4`**: запрос принимает только клик или `Enter`,
`Enter` открывает меню, ввод в меню разбирается своим кодом.

```
--- МЕНЮ VID ---
  рамка : 0,030 x 40,000 м (X x Y)
  тип   : СИНЕЕ (только попавшие целиком)

  1 или Р — размеры рамки
  2 или Т — тип выделения: синее / зелёное
  0 или К — выйти из команды
  Enter   — вернуться к выделению
Выбор:
```

`Esc` — быстрый выход.

### Ревизии v3 и v4 — метания по ложному следу (перекрыты v5)

v3 перевела опции на цифры, решив, что виновата кириллица в `initget`.
v4 вернула русские слова, когда выяснилось, что кириллика ни при чём.
Обе версии ошибались в диагнозе: проблема была не в **словах**, а в самом
механизме `initget`, который в этой установке не работает вовсе. Итог —
v5, где `initget` не используется.

## 3. Вход

- Источник данных: ручной ввод в командной строке AutoCAD/Civil 3D.
- Файл-пример не требуется: команда не читает файлы, работает с текущим DWG.

### Пример входных данных

Первый запуск за сеанс — задаётся шаблон:

```
Команда: VID
Размер по Y (сверху вниз), м: 40,000
Размер по X (слева направо), м: 0,030
[i] Шаблон сохранён: 0,030 x 40,000 м (X x Y).
VID: рамка 0,030 x 40,000 м (X x Y)  |  тип СИНЕЕ (только попавшие целиком)
Левый верхний угол области [Размеры/Тип]: <клик>
```

Все следующие запуски — один клик:

```
Команда: VID
VID: рамка 0,030 x 40,000 м (X x Y)  |  тип ЗЕЛЁНОЕ (всё, чего коснулась рамка)
Левый верхний угол области [Размеры/Тип]: <клик>
```

## 4. Выход

Набор объектов, выделенных с ручками (grips) — как если бы Шамиль выделил их
мышью. Выделение остаётся активным после завершения команды, поэтому сразу
можно нажать `Delete`, `Move`, `Copy` или задать свойства.

Никакой геометрии в чертёж команда не добавляет.

### Пример результата

```
[i] Область ПСК: X 1449070.000 ... 1449110.000   Y 656400.000 ... 656412.500
[i] Выделено объектов: 137
```

## 5. Сценарий использования

1. Загрузить `src/lisp/commands/vid.lsp` через `APPLOAD`.
2. Ввести команду `VID`.
3. **Только в первый раз**: ввести размер по `Y` (сверху вниз), затем по `X`
   (слева направо).
4. Кликнуть точку — она станет левым верхним углом рамки.
5. Объекты выделяются с ручками, команда завершается.

Дальше каждый вызов `VID` — это сразу шаг 4: команда показывает текущий
шаблон и ждёт клик. Подтверждать размеры не нужно.

### Опции в строке запроса

| Опция | Что делает |
|---|---|
| `Размеры` (`Р`) | Перезадать размеры `Y` и `X` |
| `Тип` (`Т`) | Переключить синее ⇄ зелёное выделение |
| `Enter` | Запасное текстовое меню (страховка) |
| `Esc` | Быстрый выход |

Кнопки кликабельны. Можно щёлкнуть мышью, набрать первую букву или слово
целиком — зарегистрировано и то, и другое, см. ревизию v6.

Шаблон живёт до закрытия чертежа или перезагрузки `vid.lsp`.

## 6. Edge-cases

| Случай | Поведение |
|---|---|
| `Enter` при выборе точки | Открывается меню; `0` в меню выходит из команды |
| `Esc` при выборе точки | Быстрый выход, ничего не выделяется |
| Первый запуск, шаблона ещё нет | Размеры спрашиваются автоматически |
| Пустой ввод размера, значения по умолчанию нет | Повтор запроса с примером `5,300` |
| Пустой ввод размера, шаблон есть | Берётся значение из шаблона |
| Ввод в меню не распознан | Сообщение `[!] Не понял`, меню показывается снова |
| Нечисловой ввод (`абв`, `5,3,7`, `--5`) | Повтор запроса с пояснением, команда не падает |
| Пробелы в размере (`5, 300`, ` 5,300 `) | Игнорируются, читается как `5,300`. Ввод берётся целой строкой (`getstring T`), поэтому обрыва на пробеле нет |
| Ноль или отрицательный размер | Отклоняется, повтор запроса: рамка нулевой площади бессмысленна |
| В области нет объектов | Сообщение `[i] Ничего не выделено`, выделение не ставится |
| Объекты на замороженных/выключенных слоях | Не выделяются — штатное поведение AutoCAD, не баг |
| Объекты на заблокированных слоях | Выделяются, но изменить их AutoCAD не даст — штатное поведение |
| Объекты пересекают границу рамки | Синий тип — **не** выделяются; зелёный — выделяются |
| Узкая рамка (< 100 мм) при синем типе | Печатается предупреждение: попадут только объекты уже рамки, обычно нужен зелёный |
| Повёрнутая ПСК | Рамка поворачивается вместе с ПСК: углы задаются в текущей ПСК и передаются как явный четырёхугольник (`_WP`/`_CP`) |
| Активен 3D-вид (не «сверху») | Рамка строится в плоскости текущей ПСК; в перспективе результат непредсказуем — работать в виде сверху |

## 7. Не в scope

- Фильтр по типу объектов (только линии, только точки и т.п.).
- Отрисовка прямоугольника рамки как объекта чертежа — команда не мусорит в DWG.
- Привязка к другим углам (левый нижний, центр) — выбран один, левый верхний.
- Рамка под произвольным углом к ПСК — рамка всегда по осям текущей ПСК
  (сама ПСК при этом может быть повёрнута, и рамка повернётся вместе с ней).
- Сохранение шаблона между сеансами AutoCAD (в реестр или в DWG).

## 8. Критерий приёмки

- [ ] Команда `VID` доступна после `(load "src/lisp/commands/vid.lsp")`
- [ ] Клик задаёт **левый верхний** угол; рамка уходит вправо и вниз
- [ ] `5,300` и `5.300` и `5,3` дают один результат — 5.300 м
- [ ] Первый запуск спрашивает размеры, **второй и далее — только клик**
- [ ] Кнопки `[Размеры/Тип]` видны, кликабельны и работают по букве
- [ ] Синий тип: объект, который рамка лишь задела, **не** выделяется
- [ ] Зелёный тип: полоса 40 м × 30 мм выделяет всё, что пересекла
- [ ] При **повёрнутой ПСК** рамка поворачивается вместе с чертежом
- [ ] После завершения команды объекты остаются выделенными с ручками
- [ ] Нечисловой ввод не роняет команду
- [ ] Esc на любом шаге не роняет команду и не оставляет мусор

## 9. Зависимости

- От других спек: нет. `VID` не связана с `SV`/`SVP`.
- От внешних библиотек: Visual LISP (`vl-string-subst`).
- От настроек Civil 3D: нет.
