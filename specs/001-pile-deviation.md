# SPEC-001: Обработка свай — отклонение между нижним и верхним сечениями

**Статус**: Черновик (на согласование)
**Дата создания**: 2026-05-03
**Автор**: AI-сессия #1 (по описанию Шамиля)
**Связанные ADR**: ADR-0001 (гибрид)

---

## 1. Зачем (Why)

Шамиль каждый день обрабатывает съёмку свай (причал, ж/б Ø1420мм, погружение
в воду). После каждой сваи: импорт CSV, перебор комбинаций по 3 точки для
двух сечений, вычисление центров, проверка наклона через стороннюю утилиту
`menuGEO`. Команд десятки, рутина монотонная. Один комплект — несколько минут
ручной работы; за день — много свай.

Цель: **одной командой** получить итоговую графику, которая сейчас собирается
руками: два круга-сечения и стрелки-отклонения от нижнего к верхнему.

## 2. Что делаем (What)

LISP-команда в Civil 3D, которая по CSV-файлу со съёмкой одной сваи:

1. Кластеризует точки по Z в три группы: нижнее сечение, верхнее сечение,
   верх сваи (одиночная).
2. Для каждого сечения перебирает все сочетания из 3 точек (C(N,3)),
   строит окружность и выбирает ту, у которой радиус минимально отличается
   от **710 мм** (норматив, диаметр сваи 1420 мм).
3. Рисует на чертеже:
   - **Красную окружность** нижнего сечения (на её Z, реальный найденный R).
   - **Зелёную окружность** верхнего сечения (на её Z, реальный найденный R).
   - От **центра нижнего** круга две стрелки (по осям X и Y чертежа),
     указывающие **куда сместился** центр верхнего относительно нижнего.
   - Под каждой стрелкой — подпись из двух чисел: реальное отклонение в мм
     и нормированное на 1 метр сваи (дельта Z).

В первой версии **точка верха сваи (TS0012 в примере) игнорируется** — она
участвует в кластеризации только чтобы не попасть в верхнее сечение.

## 3. Вход

- **Источник**: CSV-файл с выгрузки тахеометра Leica TS10.
- **Формат**: `Name,X,Y,Z` (без заголовка строки или с заголовком — оба
  должны поддерживаться).
- **Содержимое**: одна свая = один файл = 7–11 строк.
- **Эталонный пример**: `samples/csv/2026-05-03-pile-sample-01.csv`.

### Пример входных данных

```
TS0022,1449131.882,656409.692,1.400
TS0021,1449131.532,656409.729,1.402
TS0020,1449131.164,656409.563,1.402
TS0019,1449130.956,656409.235,1.400
TS0018,1449130.959,656408.791,1.402
TS0017,1449130.963,656408.784,2.397
TS0016,1449130.929,656409.136,2.400
TS0015,1449131.085,656409.472,2.404
TS0014,1449131.473,656409.703,2.401
TS0013,1449131.913,656409.675,2.403
TS0012,1449130.904,656409.000,5.807
```

### Что говорят данные

- Z от 1.400 до 1.402 — **нижнее сечение** (5 точек, разброс 2 мм)
- Z от 2.397 до 2.404 — **верхнее сечение** (5 точек, разброс 7 мм)
- Z = 5.807 — **верх сваи** (одна точка, далеко по Z от обеих групп)
- Между нижним и верхним: dZ ≈ 1.000 м

## 4. Выход

Команда добавляет в текущий чертёж следующие объекты на специальном слое
`GC-Сваи`:

| Объект | Где / что | Слой / цвет |
|---|---|---|
| Окружность нижнего сечения | в найденном центре, Z = средний по группе нижних, R = найденный | `GC-Сваи-Низ`, цвет `Red` |
| Окружность верхнего сечения | в найденном центре, Z = средний по группе верхних, R = найденный | `GC-Сваи-Верх`, цвет `Green` |
| Стрелка по X | от центра нижнего, длина = R + 0.20 м, направление по знаку (X_верх − X_низ) | `GC-Сваи-Отклонения` |
| Стрелка по Y | аналогично, по знаку (Y_верх − Y_низ) | `GC-Сваи-Отклонения` |
| Подпись X-стрелки | под/рядом со стрелкой, формат "12 мм (12 мм/1м)" | `GC-Сваи-Текст` |
| Подпись Y-стрелки | аналогично | `GC-Сваи-Текст` |

Все три новых слоя должны существовать после команды (создаются, если их нет).

### Формула подписи

```
dX_mm = (X_верх − X_низ) × 1000           # реальное отклонение по X, мм
dY_mm = (Y_верх − Y_низ) × 1000
dZ_m  =  Z_верх − Z_низ                    # обычно ≈1 м, но не всегда
dX_per_m = dX_mm / dZ_m                   # нормированное на 1 м
dY_per_m = dY_mm / dZ_m
```

Подпись X-стрелки: `|dX_mm| мм (|dX_per_m| мм/1м)` — модули, направление
показывает стрелка.

### Допуск

Норматив: **20 мм / 1 метр сваи**. Если |dX_per_m| или |dY_per_m| > 20 —
это **превышение допуска**. В первой версии: подпись пишется обычным цветом
текста; индикация превышения — отдельный пункт в Backlog.

## 5. Сценарий использования

1. Шамиль открывает свой рабочий DWG в Civil 3D.
2. Загружает наш набор LISP (`(load "путь/gc-pile.lsp")`) — один раз за сессию.
3. Вводит команду `gc-pile`.
4. Открывается стандартный диалог выбора файла → выбирает CSV сваи.
5. Команда читает файл, кластеризует, считает, рисует все объекты.
6. В консоль выводится сводка:
   ```
   Свая обработана:
     Низ:  центр (X, Y, Z), R = 0.7XX м (отклонение от нормы NN мм)
     Верх: центр (X, Y, Z), R = 0.7XX м (отклонение от нормы NN мм)
     Отклонение в плане:  dX = ±NN мм (NN мм/1м), dY = ±NN мм (NN мм/1м)
     dZ между сечениями = X.XXX м
   ```
7. Шамиль визуально проверяет результат в чертеже.

## 6. Edge-cases

| Случай | Поведение |
|---|---|
| В CSV меньше 6 точек (3 нижних + 3 верхних — минимум) | Ошибка с понятным русским сообщением. Не рисуем ничего. |
| Кластеризация по Z не выявляет 2 чёткие группы (разброс по Z слишком велик, нет «провала» между группами) | Ошибка: «Не удалось разделить нижнее и верхнее сечение по Z. Проверьте съёмку». |
| Только одна группа (всё на одной отметке) | Ошибка: «Найдено только одно сечение». |
| Радиус найденной окружности отличается от 710 мм более чем на 50 мм | Предупреждение в консоль, но рисуем (Шамиль решит). |
| 3 точки коллинеарны (нельзя построить круг) | Эта тройка пропускается; перебор продолжается. |
| Файл не CSV / битая строка | Ошибка с указанием строки. |
| Файл содержит точки от **нескольких** свай | Не наш случай в MVP. Возвращаем ошибку «обнаружено более 3 групп по Z — это не одна свая». |
| Команда уже отрисовала эту сваю (объекты есть) | В MVP: рисуем поверх. Очистку отложим. |

## 7. Не в scope (MVP)

- **Точка верха сваи** не оформляется визуально (ни круга, ни подписи Z).
  Только участвует в кластеризации, чтобы её отделить.
- **Сравнение с проектом** (где свая должна стоять по проекту) — не делаем.
  Только взаимное отклонение нижнего и верхнего.
- **Имя сваи** в чертеже не подписываем (берётся ли откуда-то — обсудим
  отдельно).
- **Цветовая индикация превышения допуска** (красный текст при > 20 мм/1м).
- **Batch-режим** (обработка папки CSV-файлов) — потом, через Python-обвязку.
- **Очистка предыдущей отрисовки** этой же сваи.
- **Параметризация диаметра сваи** — пока константа 1420 мм / 710 мм. Если на
  объекте появятся сваи другого диаметра — добавим параметр.

## 8. Критерий приёмки

Запуск `gc-pile` на `samples/csv/2026-05-03-pile-sample-01.csv`:

- [ ] В чертеже создано **3 новых слоя** (если их не было): `GC-Сваи-Низ`,
      `GC-Сваи-Верх`, `GC-Сваи-Отклонения`, `GC-Сваи-Текст`.
- [ ] Появилась **красная окружность** на Z ≈ 1.401 в районе X≈1449131.3,
      Y≈656409.4, R ≈ 0.710 м (±несколько мм).
- [ ] Появилась **зелёная окружность** на Z ≈ 2.401 в районе X≈1449131.3,
      Y≈656409.3, R ≈ 0.710 м.
- [ ] От центра красной (нижней) идут **две стрелки**: по X и по Y чертежа.
      Направление каждой соответствует знаку (X_верх−X_низ) и (Y_верх−Y_низ).
- [ ] Под каждой стрелкой **подпись** из двух чисел:
      `<реальное> мм (<реальное/dZ> мм/1м)`.
- [ ] В консоли — сводка по формату из §5.
- [ ] Для всех edge-cases из §6 выводится понятное русское сообщение,
      некорректные объекты не создаются.

## 9. Зависимости

- **От других спек**: нет.
- **От внешних библиотек**: нет (чистый AutoLISP, без Visual LISP COM, чтобы
  работало стабильнее).
- **От настроек Civil 3D**: команда работает в любом DWG; ничего не предполагаем
  про шаблоны/штампы.
