# SPEC-001: Обработка свай — отклонение между нижним и верхним сечениями

**Статус**: Согласовано (v2 после первого прогона у Шамиля)
**Дата создания**: 2026-05-03
**Дата согласования**: 2026-05-03
**Дата ревизии**: 2026-05-03 (фидбек после прогона: см. §11)
**Автор**: AI-сессия #1 (по описанию Шамиля)
**Связанные ADR**: ADR-0001 (гибрид)

---

## 1. Зачем (Why)

Шамиль каждый день обрабатывает съёмку свай (причал, ж/б Ø1420мм, погружение
в воду). После каждой сваи: импорт точек, перебор комбинаций по 3 точки для
двух сечений, вычисление центров, проверка наклона через стороннюю утилиту
`menuGEO`. За день — много свай, рутина монотонная.

Цель: **одной командой** получить итоговую графику, которая сейчас собирается
руками: два круга-сечения, стрелки и подписи отклонений от нижнего к верхнему.

## 2. Что делаем (What)

LISP-команда **`sv`** в Civil 3D. Пользователь импортировал свою съёмку
(стандартными средствами Civil 3D — точки уже в чертеже). Команда:

1. Спрашивает режим выбора точек:
   - **`1`** (по умолчанию) — пользователь выделил все 11 точек одной сваи;
     алгоритм кластеризует их по Z автоматически.
   - **`2`** — команда последовательно просит указать: «нижние точки»,
     «верхние точки», «верх сваи».
2. Из выбранных точек извлекает X, Y, Z (поддерживаются `AcDbPoint`,
   `AeccDbCogoPoint`, блоки — берётся точка вставки).
3. Для нижнего и верхнего сечения отдельно: перебирает все сочетания из 3
   точек C(N,3), строит окружность, выбирает ту, у которой `|R − 710мм|`
   минимальный (норматив, диаметр 1420 мм).
4. Рисует на чертеже:
   - **Красную окружность** нижнего сечения (на её Z, реальный найденный R).
   - **Зелёную окружность** верхнего сечения (на её Z, реальный найденный R).
   - От **центра нижнего** круга две стрелки (длина 400 мм, параметризовано) —
     по X и по Y чертежа, направления по знакам (X_верх − X_низ) и (Y_верх − Y_низ).
   - Под/рядом со стрелкой подпись — **одно целое число**, отклонение,
     нормированное на 1 метр сваи (мм/1м). Без единиц измерения.

В первой версии **точка верха сваи в режиме `1` участвует только в
кластеризации** (как одиночная самая высокая по Z) и в графике не отрисовывается.
В режиме `2` пользователь её всё равно указывает — но визуально она тоже
не рисуется.

## 3. Вход

- **Источник**: **точки уже в текущем DWG** (импортированы Шамилем стандартными
  средствами Civil 3D из CSV/выгрузки тахеометра).
- **Поддерживаемые типы объектов в выборке**:
  - `AcDbPoint` (обычная точка AutoCAD)
  - `AeccDbCogoPoint` (COGO Point Civil 3D)
  - блок (`AcDbBlockReference`) — берётся точка вставки
- **Объекты других типов в выборке** — игнорируются с предупреждением.
- **Эталонный sample CSV для построения теста**:
  `samples/csv/2026-05-03-pile-sample-01.csv`. Загружается в Civil 3D
  стандартным Insert COGO Points → Import Points; затем используется как
  вход для команды.

### Пример входных данных (сырых, до импорта в чертёж)

```
TS0022,1449131.882,656409.692,1.400
TS0021,1449131.532,656409.729,1.402
TS0020,1449131.164,656409.563,1.402
TS0019,1449130.956,656409.235,1.400
TS0018,1449130.959,656408.791,1.402
TS0017,1449130.963,656408.784,2.397
TS0016,1449130.929,656409.136,2.400
TS0015,1449131.085,656409.472,2.404
TS0014,1449131.473,656409.703,2.401
TS0013,1449131.913,656409.675,2.403
TS0012,1449130.904,656409.000,5.807
```

### Что говорят данные

- Z от 1.400 до 1.402 — **нижнее сечение** (5 точек, разброс 2 мм)
- Z от 2.397 до 2.404 — **верхнее сечение** (5 точек, разброс 7 мм)
- Z = 5.807 — **верх сваи** (одна точка, далеко по Z от обеих групп)
- Между нижним и верхним: dZ ≈ 1.000 м

## 4. Выход

Команда добавляет в текущий чертёж объекты на специальных слоях:

| Объект | Где / что | Слой / цвет |
|---|---|---|
| Окружность нижнего сечения | в найденном центре, Z = средний по группе нижних, R = найденный | `GC-Сваи-Низ`, цвет `Red` |
| Окружность верхнего сечения | в найденном центре, Z = средний по группе верхних, R = найденный | `GC-Сваи-Верх`, цвет `Green` |
| Стрелка X | от центра нижнего, длина **400 мм** (параметр), направление по знаку (X_верх − X_низ) | `GC-Сваи-Отклонения` |
| Стрелка Y | аналогично, длина 400 мм по знаку (Y_верх − Y_низ) | `GC-Сваи-Отклонения` |
| Текст X-стрелки | целое число (мм/1м) под серединой стрелки, ротация 0 | `GC-Сваи-Текст`, шрифт СПДС (`gostb`) |
| Текст Y-стрелки | целое число (мм/1м) сбоку от середины стрелки, ротация 90°. Y↑ → слева, Y↓ → справа. | `GC-Сваи-Текст`, шрифт СПДС |

Высота текста — **0.100 м** (параметр). Все слои создаются автоматически.

### Формула подписи

```
dX_mm    = (X_верх − X_низ) × 1000        # реальное по X, мм
dY_mm    = (Y_верх − Y_низ) × 1000
dZ_m     =  Z_верх − Z_низ                 # обычно ≈1 м, но не всегда
dX_per_m = dX_mm / dZ_m                   # нормированное на 1 м, мм
dY_per_m = dY_mm / dZ_m
```

**Подпись стрелки = `<|dX_per_m| округл. до целого>` (только число, без единиц).**
Реальное `dX_mm` НЕ выводится в чертёж — только в сводку в командной строке.
Знак не пишется — направление показывает стрелка.

### Допуск

Норматив **20 мм / 1 м**. В первой версии цветовая индикация превышения **не
делается** — это в Backlog (см. §7).

## 5. Сценарий использования

1. Шамиль открывает рабочий DWG в Civil 3D.
2. Импортирует CSV-выгрузку одной сваи стандартным Civil 3D-импортом — точки
   появляются в чертеже.
3. Загружает наш набор LISP (`(load "путь/sv.lsp")`) — один раз за сессию
   (или подключает через `acaddoc.lsp`).
4. Вводит команду `SV`. Появляется prompt:
   ```
   Режим выбора точек [1=все сразу / 2=по группам] <1>:
   ```
5. **Если `1`**: prompt «Выделите все точки сваи (низ+верх+верхушка):». Шамиль
   рамкой выделяет 11 точек → Enter. Команда сама кластеризует по Z.
6. **Если `2`**: три последовательных prompt'а:
   - «Выделите точки нижнего сечения:» → Шамиль выделяет → Enter
   - «Выделите точки верхнего сечения:» → Enter
   - «Укажите точку верха сваи:» → одна точка → Enter
7. Команда обрабатывает, рисует объекты.
8. В консоль выводится сводка:
   ```
   Свая обработана:
     Низ:  центр (X, Y, Z), R = 0.7XX м (отклонение от нормы NN мм)
     Верх: центр (X, Y, Z), R = 0.7XX м (отклонение от нормы NN мм)
     dX = ±NN мм (NN мм/1м), dY = ±NN мм (NN мм/1м)
     dZ между сечениями = X.XXX м
   ```
9. Шамиль визуально проверяет результат.

## 6. Edge-cases

| Случай | Поведение |
|---|---|
| Меньше 6 точек (3 нижних + 3 верхних — минимум) | Ошибка с понятным русским сообщением. Не рисуем ничего. |
| **Режим 1**: ровно 6 точек | 1 разрез → 2 группы (нижнее + верхнее, без верхушки). |
| **Режим 1**: ≥7 точек | 2 разреза по самым большим разрывам Z → 3 группы. Верхушка игнорируется. |
| **Режим 1**: меньше 3 точек в одной из групп | Ошибка: «В нижнем/верхнем сечении меньше 3 точек». |
| **Режим 1**: больше 3 групп по Z | Невозможно с адаптивной кластеризацией — она всегда даёт ≤ 3 группы. Если когда-то возникнет — значит изменилась структура съёмки, переоценим. |
| Радиус найденной окружности отличается от 710 мм более чем на 50 мм | Предупреждение в консоль («R = 0.6XX, далеко от нормы»), но рисуем (Шамиль решит). |
| 3 точки коллинеарны (нельзя построить круг) | Эта тройка пропускается; перебор продолжается. |
| Объект в выборке не AcDbPoint/COGO Point/блок | Игнорируем с предупреждением «пропущено N объектов неподдерживаемого типа». |
| Команда уже отрисовала эту сваю (объекты есть) | В MVP: рисуем поверх, не очищаем. Очистка отложена. |

## 7. Не в scope (MVP)

- **Точка верха сваи** не оформляется визуально (ни круга, ни подписи Z).
- **Сравнение с проектом** (где свая должна стоять по проекту) — не делаем.
- **Имя сваи** в чертеже не подписывается.
- **Цветовая индикация превышения допуска** (красный текст при > 20 мм/1м).
- **Batch-режим** (обработка нескольких свай за раз) — потом, через Python.
- **Загрузка из CSV прямо в команду** — потом (в MVP импорт делает Civil 3D).
- **Очистка предыдущей отрисовки** этой же сваи.
- **Параметризация диаметра сваи** — пока константа 1420 мм / 710 мм. Если на
  объекте появятся сваи другого диаметра — добавим параметр.
- **Параметризация длины стрелки и высоты текста** — пока константы в начале
  файла `sv.lsp` (`*gc-pile-arrow-len*`, `*gc-pile-text-h*`). Шамиль может
  править вручную. Полноценная параметризация через prompt — в Backlog.

## 8. Критерий приёмки

Сценарий: импортировать `samples/csv/2026-05-03-pile-sample-01.csv` в Civil 3D
стандартным импортом → запустить `SV` в режиме `1` → выделить все 11 точек.

- [ ] В чертеже создано 4 новых слоя: `GC-Сваи-Низ`, `GC-Сваи-Верх`,
      `GC-Сваи-Отклонения`, `GC-Сваи-Текст`.
- [ ] Появилась **красная окружность** на Z ≈ 1.401 в районе X≈1449131.3,
      Y≈656409.4, R ≈ 0.710 м (±несколько мм).
- [ ] Появилась **зелёная окружность** на Z ≈ 2.401 в районе X≈1449131.3,
      Y≈656409.3, R ≈ 0.710 м.
- [ ] От центра красной (нижней) идут две стрелки длиной **400 мм**:
      одна по X чертежа, другая по Y. Направления по знакам.
- [ ] У X-стрелки подпись (целое число, мм/1м) под серединой, ротация 0.
      У Y↑ — слева от середины с ротацией 90°. У Y↓ — справа с ротацией 90°.
      Шрифт — СПДС (`gostb` с fallback на Standard). Высота 100 мм.
- [ ] В консоли — сводка по формату из §5.
- [ ] Прогон в режиме `2` на тех же точках даёт идентичный результат.
- [ ] Edge-cases из §6 дают понятные русские сообщения, без частичной
      отрисовки.

## 9. Зависимости

- **От других спек**: нет.
- **От внешних библиотек**: нет (чистый AutoLISP / Visual LISP).
- **От настроек Civil 3D**: должен быть установлен СПДС-шрифт (`gostb` или
  аналог). Если не найден — fallback на `Standard`.

## 11. Журнал ревизий

### v2 — 2026-05-03 (после первого прогона у Шамиля)

Что изменено по итогам реальной проверки:

1. **Кластеризация по Z** — с фиксированного порога (100 мм) на адаптивную
   («2 самых больших разрыва»). **Root cause**: при выборке с большим
   разбросом по Z старый алгоритм находил 4+ групп → ошибка. Новый алгоритм
   всегда даёт ровно 3 группы (или 2 при N=6).
2. **Длина стрелки**: 200 мм → **400 мм**.
3. **Высота текста**: 300 мм → **100 мм**.
4. **Формат подписи**: `"NN мм (NN мм/1м)"` → **только целое число**
   (нормированное на 1 м, без единиц).
5. **Положение текста** относительно стрелки (по запросу Шамиля):
   - X-стрелка → текст под серединой, ротация 0
   - Y-стрелка вверх → текст слева от середины, ротация 90°
   - Y-стрелка вниз → текст справа от середины, ротация 90°
6. Обе константы (длина стрелки и высота текста) выведены в начало `sv.lsp` —
   Шамиль может править вручную без AI.

### v1 — 2026-05-03 (исходная версия)

Первая согласованная версия. Команда `sv`, два режима, фиксированный порог
кластеризации, стрелки 200 мм, текст 300 мм, подпись из двух чисел.
