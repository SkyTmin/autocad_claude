# SPEC-003: Продление сваи до заданной высотной отметки

**Статус**: v13 реализовано, требуется ручной прогон в Civil 3D  
**Дата создания**: 2026-05-11  
**Главный файл**: `src/lisp/commands/sv.lsp`  
**Команда**: `SVP`  
**Связанные спеки**: SPEC-001, SPEC-002

---

## 1. Зачем

После погружения сваи режутся на проектной/рабочей высотной отметке, которая часто находится выше фактической съемки. `SVP` строит сечение сваи на заданной Z-отметке по двум фактически заснятым сечениям.

В v13 команда также сравнивает новое построенное сечение с проектным центром сваи: пользователь выбирает проектный круг или проектную точку, а `SVP` рисует проектное отклонение от проектного центра к новому центру сечения.

## 2. Пользовательский сценарий

1. Пользователь загружает `sv.lsp` через APPLOAD или `(load "...")`.
2. Запускает `SVP`.
3. Выделяет рамкой все точки свай так же, как в `SV` режим `1`.
4. Вводит целевую высотную отметку Z в метрах проекта.
5. Выделяет рамкой проектные круги или проектные точки.
6. Команда строит новое сечение для каждой найденной сваи.
7. Если проектный центр найден рядом, команда строит стрелки и подписи проектного отклонения.

Если проектные объекты не выбраны, `SVP` строит только новые сечения, как v12.

## 3. Вход

- Фактические точки: `POINT`, `AECC*POINT`, `AEC*POINT`.
- Проектные объекты: `CIRCLE`, `POINT`, `AECC*POINT`, `AEC*POINT`.
- Для `CIRCLE` проектный центр берется из центра окружности.
- Для точки проектный центр берется из ее XY-координат.
- Z проектного объекта игнорируется: графика проектного отклонения строится на целевой Z-отметке среза.

Для каждой сваи по-прежнему нужны минимум 2 сечения и минимум 3 валидные точки на каждое сечение.

## 4. Алгоритм

`SVP` переиспользует стабильную логику `SV v11`:

1. Прочитать выбранные точки.
2. Сгруппировать точки по XY в сваи.
3. Внутри каждой сваи сгруппировать точки по Z.
4. Удалить изолированную пару отметчиков высоты через `gc-pile-strip-hm`.
5. Найти нижнее и верхнее сечения, построив окружности по лучшим 3 точкам.
6. Посчитать центр нового сечения на целевой отметке:

```text
k = (Ztarget - Zlow) / (Zhigh - Zlow)
Xtarget = Xlow + k * (Xhigh - Xlow)
Ytarget = Ylow + k * (Yhigh - Ylow)
Ztarget = введенная отметка
```

Проектное отклонение:

```text
dX = Xtarget - Xproject
dY = Ytarget - Yproject
```

Подписи `dX/dY` выводятся в целых миллиметрах, без деления на метр. Направление задается стрелкой.

## 5. Сопоставление с проектом

- Для каждого нового центра `SVP` берет ближайший неиспользованный проектный центр.
- Максимальное расстояние связки: `*gc-pile-project-match-max* = 2.000 м`.
- Если ближайший проектный центр дальше лимита, новое сечение все равно строится, но проектное отклонение для этой сваи пропускается с сообщением в консоль.
- Каждый проектный центр используется только один раз за запуск.

## 6. Выход

| Объект | Где / что | Слой / цвет |
|---|---|---|
| Окружность нового сечения | центр `(Xtarget, Ytarget, Ztarget)`, радиус `0.710 м` | `GC-Сваи-Срез`, цвет 4 |
| Стрелки проектного отклонения | от проектного центра по X/Y в сторону нового центра | `GC-Сваи-Проект-Отклонения`, цвет 2 |
| Подписи проектного отклонения | абсолютные `dX/dY` в мм | `GC-Сваи-Проект-Текст`, цвет 2 |

`SVP` не рисует исходные нижнее/верхнее фактические сечения и не меняет поведение команды `SV`.

## 7. Edge-cases

| Случай | Поведение |
|---|---|
| Целевая отметка выше/ниже съемки | Строится без предупреждения, как экстраполяция. |
| Целевая отметка между сечениями | Строится как интерполяция. |
| Проектные объекты не выбраны | Строятся только новые сечения, без проектных отклонений. |
| Проектных центров меньше, чем свай | Для оставшихся свай проектное отклонение пропускается. |
| Проектный центр дальше 2 м | Сечение строится, проектное отклонение пропускается. |
| В сечении меньше 3 точек | Свая пропускается; issue #001 не решается в рамках `SVP`. |

## 8. Критерии приемки

- [ ] `sv.lsp` загружается и сообщает `v13`.
- [ ] `SVP` строит новые сечения как v12.
- [ ] `SVP` принимает проектные круги и проектные точки.
- [ ] Стрелки и подписи проектного отклонения строятся на Z среза.
- [ ] Подписи показывают абсолютные миллиметры, не `мм/1м`.
- [ ] Ближайший проектный центр используется только один раз.
- [ ] Далекий проектный центр не дает ложной связки.
- [ ] `SV` после изменений работает как раньше.

## 9. Статус проверки

Код написан и проверен по структуре/диффу вне Civil 3D. Финальная приемка требует ручного запуска у Шамиля в Civil 3D.
