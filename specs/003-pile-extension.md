# SPEC-003: Продление сваи до заданной высотной отметки

**Статус**: Реализовано, требуется ручной прогон в Civil 3D  
**Дата создания**: 2026-05-11  
**Связанные спеки**: SPEC-001, SPEC-002  
**Главный файл**: `src/lisp/commands/sv.lsp`  
**Команда**: `SVP`

---

## 1. Зачем

После погружения сваи позже режутся на проектной или рабочей высотной отметке. Часто эта отметка находится выше или ниже фактической съемки. Команда `SV` уже умеет находить нижнее и верхнее сечение сваи и считать наклон по центрам. `SVP` использует тот же наклон, чтобы построить сечение сваи на заданной отметке.

Цель: одной командой построить окружность сечения сваи на нужной Z-отметке без ручного пересчета координат центра.

## 2. Пользовательский сценарий

1. Пользователь загружает `sv.lsp` через APPLOAD или `(load "...")`.
2. Запускает команду `SVP`.
3. Выделяет рамкой все точки свай так же, как в `SV` режим `1`.
4. Вводит целевую высотную отметку Z в метрах проекта.
5. Команда строит новое сечение для каждой найденной сваи.

`SVP` не спрашивает режим `1/2`: используется только автоматический сценарий выбора всех точек сразу.

## 3. Вход

- Точки уже импортированы в текущий DWG.
- Поддерживаемые объекты те же, что у `SV`: `POINT`, `AECC*POINT`, `AEC*POINT`.
- Для каждой сваи нужны минимум 2 сечения, и в каждом сечении минимум 3 валидные точки.
- Одна целевая отметка применяется ко всем сваям за текущий запуск команды.

## 4. Алгоритм

Для поиска свай `SVP` переиспользует стабильную логику `SV v11`:

1. Прочитать выбранные точки.
2. Сгруппировать их по XY в сваи.
3. Внутри каждой сваи сгруппировать точки по Z.
4. Удалить изолированную пару отметчиков высоты через `gc-pile-strip-hm`.
5. Для нижнего и верхнего сечения построить окружности по лучшим 3 точкам.
6. Взять центры нижнего и верхнего сечения как опорную линию наклона.

Центр на целевой отметке считается линейно:

```text
k = (Ztarget - Zlow) / (Zhigh - Zlow)
Xtarget = Xlow + k * (Xhigh - Xlow)
Ytarget = Ylow + k * (Yhigh - Ylow)
Ztarget = введенная отметка
```

Формула применяется одинаково для интерполяции между сечениями и экстраполяции выше/ниже фактической съемки.

## 5. Выход

Команда строит только новое сечение:

| Объект | Где / что | Слой / цвет |
|---|---|---|
| Окружность сечения на целевой отметке | центр `(Xtarget, Ytarget, Ztarget)`, радиус `0.710 м` | `GC-Сваи-Срез`, цвет 4 |

`SVP` не рисует стрелки, подписи отклонений, нижнее сечение и верхнее сечение. В консоль выводится краткая сводка: целевая Z, центр, радиус и опорные Z нижнего/верхнего сечения.

## 6. Edge-cases

| Случай | Поведение |
|---|---|
| Целевая отметка выше верхнего сечения | Строим без предупреждения. Это основной сценарий команды. |
| Целевая отметка ниже нижнего сечения | Строим без предупреждения. |
| Целевая отметка между сечениями | Строим интерполированное сечение. |
| Найдено меньше 2 сечений | Свая пропускается с диагностикой от общей логики `SV`. |
| В сечении меньше 3 точек | Свая пропускается; issue #001 не решается в рамках `SVP`. |
| `dZ` между опорными сечениями слишком мал | Свая пропускается, чтобы не делить на почти ноль. |

## 7. Не в scope

- Построение окружности по 2 точкам + нормативному радиусу.
- Отдельная отметка для каждой сваи внутри одного запуска.
- Подписи, стрелки или сравнение с проектным центром.
- Автоматическая очистка старых сечений `SVP`.
- Изменение поведения команды `SV`.

## 8. Критерии приемки

- [ ] `SV` после изменений работает как раньше.
- [ ] `SVP` доступна после загрузки `sv.lsp`.
- [ ] `SVP` принимает выбор всех точек рамкой как `SV` режим `1`.
- [ ] При вводе отметки выше верхнего сечения строится окружность на слое `GC-Сваи-Срез` с радиусом `0.710`.
- [ ] При вводе отметки между сечениями строится интерполированное сечение.
- [ ] При вводе отметки ниже нижнего сечения строится экстраполированное сечение.
- [ ] Для свай с неполными сечениями сохраняется текущее ограничение `>=3` точки на сечение.

## 9. Статус проверки

Код написан и статически проверяется вне Civil 3D. Финальная приемка требует ручного запуска у Шамиля в Civil 3D.
