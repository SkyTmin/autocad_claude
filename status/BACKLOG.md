## Современный интерфейс картограммы (после функционала)

**Заявлено**: 2026-09-01. **Статус**: после того, как расчёт заработает.

Сейчас окно на DCL: работает везде, без сборки и без внешних файлов, но
выглядит как системный диалог девяностых. Нет вкладок, иконок, шрифтов,
цветного текста, изменения размера, живого предпросмотра.

Шамиль: «сначала функционал, потом красота, даже если придётся двумя-тремя
файлами работать».

Что даст переход на .NET-палитру:

- нормальное окно: вкладки, иконки, таблицы, подсказки;
- можно пристыковать сбоку как палитру Civil 3D, а не модальное окно;
- живой предпросмотр сетки прямо в окне;
- взаимодействие с чертежом без закрытия окна — сейчас кнопки «Указать»
  вынужденно закрывают диалог.

Цена: сборка `.dll` под версию Civil 3D, `NETLOAD`, комплект из нескольких
файлов, пересборка при обновлении CAD.

Подготовка уже сделана: настройки живут отдельным списком, расчёт не знает,
откуда они взялись. Значит источник настроек меняется без правки математики.

**Промежуточный вариант, если до .NET не дойдёт:** в DCL можно рисовать
векторы в квадратиках-картинках — то есть добавить в окно схемку сетки,
стрелку угла и легенду штриховок. Дёшево и заметно улучшает читаемость.

## Картограмма для линейных объектов (дороги)

**Заявлено**: 2026-09-01. **Статус**: после площадочного варианта (SPEC-009).

Для дорог картограмма строится не по габаритам площадки, а **вдоль трассы**:

| Вход | Замечание |
|---|---|
| Поверхность чёрная, поверхность красная | как в площадочном режиме |
| **Трасса (ось)** | дополнительный объект |
| **Пикетаж: начальный и конечный** | формат «ПК + смещение» |
| Шаг сетки **вдоль оси** | отдельно |
| Шаг сетки **поперёк оси** | отдельно |

Ряды сетки идут по пикетажу, столбцы — поперечниками. Вся математика объёмов
та же, что в площадочном варианте (`docs/formulas.md`), меняется только
раскладка сетки.

Дороги заявлены в области проекта (`CLAUDE.md` §1), так что режим пригодится.
Делать после того, как площадочный вариант отработает и будет сверен
с эталоном.

## Шаблон исполнительной схемы по сваям (параметрическая схема)

**Заявлено**: 2026-08-24, Шамиль. **Статус**: отложено, вернуться позже.

**Задача.** Исполнительных схем на сваи очень много, они однотипные:
графика одна и та же, меняются только цифры, часть из которых считается
по формулам. Нужно свести работу к «ввёл нужные значения в нужных местах».

**Что выяснено при обсуждении.** Штатными средствами AutoCAD это не решается:

| Механизм | Что умеет | Чего не хватает |
|---|---|---|
| Блок с атрибутами | схема как один объект, цифры в полях | **формул нет** |
| Поля (`FIELD`) | свойства объектов, дата, имя листа | арифметику между атрибутами не умеют |
| Динамический блок | тянуть, множить, видимость | формул тоже нет |
| Таблица с формулами | мини-Excel в чертеже | годится для ведомости, не для графики |
| Связь с Excel | числа обновляются | только таблица, графика мимо |
| Параметрические зависимости | геометрия по формулам | тяжело поддерживать, избыточно |

**Предлагаемый подход — шаблон-блок плюс команда-заполнитель:**

1. графика схемы уходит в блок и больше не меняется;
2. каждое место с цифрой становится **атрибутом** с именем
   (`H_ПРОЕКТ`, `H_ФАКТ`, `OTKL`, `N_СВАИ`);
3. пишется **карта переменных**: что вводится, что считается, по какой формуле;
4. команда вставляет блок, спрашивает **только исходные**, считает
   производные, заполняет все атрибуты разом;
5. отдельная команда **пересчёта** уже вставленной схемы — без неё
   любая опечатка означает «вставляй заново».

**Почему это сильнее готовых механизмов:** формулы всё равно считать кодом,
а часть значений вообще не надо спрашивать — `SV`/`SVP` уже считают отклонения
свай по съёмке, данные лежат в чертеже. Блок при этом остаётся обычным блоком:
открывается без лиспа, редактируется руками, идёт в ведомость через
`ДАННЫЕИЗВЛ`.

**Чего не хватает, чтобы начать (DoR):**

1. **сама схема** — DWG (лучше) или скриншот, положить в `samples/dwg/`;
2. **формулы** — что из чего считается;
3. **что меняется** от схемы к схеме: только цифры? размеры? количество
   элементов (на одной три сваи, на другой восемь)?
4. откуда исходные: из съёмки в чертеже, руками, из CSV/Excel;
5. сколько схем за раз — по одной или пачкой на участок;
6. одна схема — один лист, или все на одном.

Пункты 1–3 критичны: без них это код по догадкам (R5).

**Потребуется ADR** (R4): выбор «блок с атрибутами» против «генерация
чертежа с нуля» разворачивать потом дорого.
