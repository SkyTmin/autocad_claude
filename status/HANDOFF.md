## Что дальше (следующая сессия делает первым)

1. Прочитать `CLAUDE.md`, этот `HANDOFF.md`, `ROADMAP.md`, `specs/001-pile-deviation.md`.
2. **Реализовать команду `sv`** в `src/lisp/commands/sv.lsp`. По плану:
   - `lib/csv.lsp` — чтение CSV (для тестов / на будущее)
   - `lib/geometry.lsp` — окружность по 3 точкам, центроид, расстояние
   - `lib/circle-fit.lsp` — перебор C(N,3), выбор min |R−710|
   - `lib/cluster.lsp` — кластеризация массива точек по Z (для режима 1)
   - `commands/sv.lsp` — интерфейс пользователя, чтение выборки, оркестрация
3. Первая итерация — **режим 1** (более частый case). Режим 2 — после
   проверки режима 1 на реальных данных.
4. По R6: код пишется, **проверяется Шамилем вручную в Civil 3D**, не на
   этой Linux-среде. Явно пометить "не проверено — требуется ручной запуск"
   в DoD.
5. После прогона Шамиля — итерируем по фидбеку до зелёного критерия приёмки.
6. Когда `sv` режим 1 работает — добавить режим 2 в этом же файле.

## Известные риски

- **AI-лень**: митигация — обязательная самопроверка DoD в чате, KPI в
  `status/QUALITY.md`.
- **Нет среды для авто-проверки LISP**: Civil 3D запускает только Шамиль.
  Первый прогон может выявить баги — итерируем.
- **AutoLISP API для COGO Points**: чтение свойств COGO Point требует
  Visual LISP `vlax-` функций. Если станет хрупко — fallback на обычный
  AcDbPoint.
- **СПДС-шрифт `gostb`**: если у Шамиля нет — fallback на Standard в коде.
