3. **Реализация — `src/lisp/commands/sv.lsp` v3**:
   - Извлечение координат: COGO Point / AcDbPoint через VL (Easting/Coordinates).
   - Окружность по 3 точкам, перебор C(N,3), выбор min `|R − 710|`.

     захвачены рамкой. **v3 фикс root cause** бага «4 группы» при повторных запусках.
   - **Кластеризация по Z**: плотные группы (порог 50 мм) → отбор 2 групп
     с наибольшим количеством точек ≥3. **v3 фикс**: устойчиво к посторонним
     одиночным точкам, точно по словам Шамиля «минимум 3 на одной высоте».
   - Слои `GC-Сваи-*`, стиль текста с fallback'ом GOSTB→ISOCPEUR→Standard.
   - Стрелки длиной 400 мм, текст 100 мм. Подпись — одно целое число (мм/1м).
   - **Положение текста (v3)**:
     - X→ → ПОД серединой, ротация 0
     - X← → НАД серединой, ротация 0   ← **v3 фикс** (было всегда под)
     - Y↑ → СЛЕВА, ротация 90°
     - Y↓ → СПРАВА, ротация 90°
   - Все константы (длина, высота, порог, фильтр) вынесены в начало файла.

4. **Прогоны Шамиля**:
   - #1: SV 1 работало только на ровно 11 точках, ломалось на >11. SV 2 —

   - #2 (v2): подтверждено что выборка хватает посторонние объекты при
     повторных запусках. Текст для X← неправильно (под, а не над).

5. **SPEC-002 v1 не сработала** — на 3 сваях команда рисовала только
   часть, на других ничего. Root cause: single-linkage склеивает соседние
   сваи (точки разных свай ближе чем точки одной сваи на крайних концах дуги).

6. **SPEC-002 v2 — переписана** на жадный поиск окружностей:
   - Z-кластеризация без изменений (низы всех свай / верхи всех свай).
   - В каждой Z-группе цикл: перебор C(N,3), окружность с min `|R−710|`
     при `|R−710| ≤ 50 мм` → её точки = в радиусе R+ε от центра. Удаляем,
     повторяем. Привязка к КОНКРЕТНОМУ центру решает проблему близких свай.
   - Сопоставление пар низ↔верх по XY-центрам (допуск 0.5м).
   Также **переписаны правила положения текста** в 4 квадранта круга
   по таблице Шамиля (формула через `sxy = sign(dx·dy)`).

## Что дальше (следующая сессия делает первым)

1. Прочитать `CLAUDE.md`, этот `HANDOFF.md`, `ROADMAP.md`,
   `specs/001-pile-deviation.md`, `specs/002-pile-multi-batch.md`,
   `src/lisp/commands/sv.lsp`.
2. Узнать у Шамиля: **результат прогона** SPEC-002 (несколько свай) и
   SPEC-001 v3 (одна свая через тот же mode 1).
3. Если работает — закрыть обе спеки, обновить QUALITY.md, переходить
   к следующей фиче из ROADMAP/Backlog.
4. Если есть баги — **root cause** (R3), правки, ревизии спек.

**Известные риски для SPEC-002**:
- Точки разных свай ближе порога XY (1.0м) — кластеры слипнутся.
  Параметр в `*gc-pile-xy-cluster*`, можно подкрутить.
- Если на одной свае нижнее и верхнее сечения сильно сместились в плане
  (наклон сваи >0.5м в плане) — пара может не сопоставиться.
  Параметр в `*gc-pile-pair-tolerance*`.
- single-linkage XY-кластеризация — `O(n²·k)`, может тормозить на 100+ точках.
  Если станет проблемой — оптимизация на отдельной итерации.
