# Модель расчёта картограммы на Python

Воспроизводит расчёт `src/lisp/commands/kg.lsp` численно, чтобы проверять
гипотезы **без прогона в Civil 3D**. Один прогон у Шамиля стоит времени
и внимания; здесь сотня вариантов перебирается за секунды.

## Зачем это появилось

К 2026-09-09 накопились отчёты `KGX` по четырём независимым чертежам.
В них есть полные дампы расходящихся квадратов: координаты каждой
вершины, рабочая отметка, флаги `ПОДПИСАН` / `УЗЕЛ`, излом, отклонение —
и рядом объём эталона. Этого достаточно, чтобы считать самим.

Дважды до этого гипотеза применялась в код и проверялась прогоном,
и дважды оказывалась вредной ([П95](../../docs/pitfalls.md),
[П96](../../docs/pitfalls.md)). Модель закрывает этот путь: гипотеза
проверяется до правки.

## Состав

| файл | что делает |
|---|---|
| `cells.json` | 118 квадратов из отчётов по четырём чертежам, 584 вершины |
| `model.py` | расчёт как в `gc-kg-vol-marked`: отсечение по знаку, наложение, масштаб, порог |
| `fit.py` | глобальный набор точек чертежа и прогон произвольного правила отбора |
| `variants.py` | варианты геометрии: резать по подписанным узлам или по полному контуру |
| `tri.py` | вариант с треугольниками на седловых квадратах |

## Проверка самой модели

    python3 -c "import sys;sys.path.insert(0,'tools/kgfit');from fit import *;print(check_reproduces())"

Модель обязана воспроизводить **наш** столбец. Сейчас: расходится 11
из 118, максимум 0,833 — остаток от того, что дамп даёт не все квадраты,
в которых лежит вершина.

**Правило: если модель не воспроизводит наш столбец — сначала чинится
модель, и только потом по ней что-то решается.** Иначе получится П96:
измерение не тем путём, которым идёт расчёт.

## Что модель уже показала (2026-09-09)

Суммарное `|наш − его|` по 117 квадратам — **14,42 м³**. Перебор:

| что меняли | результат |
|---|---|
| порог отклонения, 0,05…0,45 | лучший 0,24 → 14,76 (−3 %) |
| порог + отсечка «шпилек» сверху | без улучшения |
| «угол 40…180° ИЛИ отклонение ≥ 0,25» | 13,07 (−14 %) |
| «короткое плечо» (густая оцифровка) | 21,4 и хуже — отклонено |
| резать полный контур вместо подписанных узлов | 15,18 — без разницы |
| без масштаба площади | 26,7 — сильно хуже |
| треугольники на седле, диагональ 1-3 | 14,74 (−3 %) |
| треугольники на седле, диагональ 2-4 | 15,15 (−0,4 %) |

**Ни одно правило отбора узлов и ни один вариант метода не объясняют
расхождение.** Максимум 14 %, и то на смещённой выборке — в дампы
попадают только расходящиеся квадраты.

Где расхождение сидит на самом деле:

* **93 квадрата из 117 (79 %)** расходятся не больше, чем на «одна
  рабочая отметка сдвинута на 1 см» — но дают лишь **24 %** массы (3,47 м³);
* **24 квадрата (21 %)** дают **76 %** массы (10,95 м³), и ни правило,
  ни метод их не объясняют.

На целых квадратах, где все четыре угла — узлы сетки и правило отбора
не участвует вовсе, расхождение **кратно 0,0625 м³** (17 случаев из 21).
А 0,0625 — это ровно `0,01 × 25 / 4`, цена изменения одной отметки
на сантиметр. То есть там расходятся сами отметки, а не расчёт.
