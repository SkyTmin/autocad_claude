# Проверка SV 4 / SV 5 — 2026-11-12

**Обновление после ревью:** по запросу пользователя исправлено в v32.
Ниже сохранён исходный разбор v31; результат исправления — в конце файла.

Проверен `src/lisp/commands/sv.lsp` v31, коммит
`43fc3cc5763f107a515df6659ea8d4313a23d3bf`, ветка
`claude/project-status-check-h0n2w`.

Запрос: проверить перебор точек и получение эллипса максимально близких
к проектным размеров, включая точное совпадение, если оно возможно.
Уточнение пользователя трактуется как близость полуосей к номиналу
0,710 / 0,727319618 м, а не привязка центра к объекту проекта.

## Что действительно перебирается

- SV 1/2/3 перебирают тройки через `gc-pile-best-circle`, выбирая радиус
  окружности ближе к 0,710 м (`src/lisp/commands/sv.lsp:308`).
- SV 4/5 используют `gc-pile-e-fit`: все переданные точки, фиксированное
  отношение осей, алгебраический МНК окружности после преобразования.
  Перебирается угол; комбинаций точек здесь нет.
- SV 4 читает у проектного эллипса только центр, после подбора сечений
  сравнивает с ним центр среза. Размеры проекта в подбор не поступают.
  SV 5 проектный объект вообще не запрашивает.

Отказ от перебора троек прямо записан в SPEC-010/011 и ADR-0010/0014.
Это расхождение метода с ожидаемым поведением, а не неработающий вызов
существующего перебора. Новый способ отбора требует обновления спецификации.

## Подтверждённые проблемы

### 1. SV 5 пропускает точное решение — issue #012

`src/lisp/commands/sv.lsp:1502–1516`: грубый шаг 5°, затем уточнение только
около одного лучшего узла. При нескольких минимумах узкий лучший минимум
может проиграть на грубой сетке и больше никогда не рассматриваться.

Контрпример: семь точек без шума на дуге 77,14° номинального эллипса,
центр (10;20), поворот 0,4 рад = 22,9183°.

| Результат | Возвращённый SV 5 | Доступный точный кандидат |
|---|---:|---:|
| Поворот большой оси, по модулю 180° | 9,912° | 22,9183° |
| Ошибка центра | 6,418 мм | менее 1e−10 мм |
| Невязка | 0,2254 мм | около машинного нуля |
| Критерий | 5,1358e−8 | 3,5788e−30 |

Оба кандидата рассчитаны одной исходной функцией `gc-pile-e-single-candidate`.
Следовательно, даже внутри текущей модели лучший вариант не гарантирован.
Уменьшение последнего шага внутри выбранного минимума эту причину не устраняет.

### 2. Номинал не участвует в подборе центра и размера — issue #013

`src/lisp/commands/sv.lsp:1150–1153`, `1168–1180`, `1481–1487`:
центр и радиус сначала определяются алгебраическим МНК без номинала.
Штраф `(b−0,710)²` добавляется потом, только при сравнении углов.
Он не даёт изменить центр/радиус при том же угле. Это ограниченный набор
кандидатов, а не минимизация общего критерия по параметрам эллипса.

Контрпример для обоих режимов: семь точек номинальной дуги 30° с
детерминированным шумом до 2 мм по каждой координате. Верхнее сечение для
SV 4 — копия нижнего, сдвинутая на 1 м по направлению наклона и на 4,5 м по Z.

- SV 5: b = 0,662841640 м; a = 0,679010886 м; ошибка центра 50,218 мм.
- SV 4: b = 0,662841627 м; a = 0,679010872 м для обоих сечений.
- Невязка выбранного эллипса около 0,509 мм, предупреждения нет:
  отличие b от нормы 47,158 мм меньше установленного порога 50 мм.
- Допустимый номинальный эллипс имеет невязку 1,386 мм на ВСЕХ тех же
  точках. Его общий критерий 1,9201e−6 против 2,2242e−3 у выбранного:
  лучше примерно в 1158 раз. Для парного критерия SV 4 вывод тот же.

Для сверки диагностический расчёт невязки и парного штрафа проверяется
на совпадение с результатами исходного LISP. Номинальный кандидат здесь
контрольный: это не подстановка эталона в рабочий расчёт и не доказательство
его единственности на реальной съёмке.

### 3. SV 4 исключает обычные точки по признаку высоты — issue #014

`src/lisp/commands/sv.lsp:1451` вызывает `gc-pile-strip-hm` (строки 288–305).
При пяти и более точках две верхние удаляются, если близки друг к другу
по Z менее чем на 2 мм и отделены от третьей минимум на 10 мм.

Контрпример через `gc-pile-e-auto`: пять точек поверхности одного наклонного
цилиндра на Z = 0 / 0 / 0 / 0,020 / 0,021 м, аналогичный верхний уровень.
Разброс 21 мм допустим для SV 4, высотных отметчиков нет. В каждое сечение
попадают только три точки; команда сообщает об удалении пары отметчиков.
Это меняет вход для подбора. На настоящем чертеже такая причина зависит
от распределения отметок и назначения выбранных точек.

## Проверки и границы результата

- `node tools/test_sv4.mjs`: существующий набор проходит, включая
  аналитические примеры, старые CSV, срезы, проектные отклонения и маршруты меню.
- `node tools/review_sv45.mjs`: 4 из 4 новых проверок не проходят на v31,
  код возврата 1. Они воспроизводят три проблемы выше: парный и одиночный
  подбор по общему критерию проверяются раздельно.
- `python3 tools/lspcheck.py src/lisp/commands/sv.lsp`: CP1251, скобки и
  ссылки на функции корректны; сообщены существующие предупреждения о
  нелокальных переменных. Полностью чистым результат линтера не является.
- Новые контрпримеры аналитические; файл проблемной наклонной сваи
  пользователя не предоставлен. Старые CSV не являются её эталоном.
- Исполнялись чистые функции исходного LISP ограниченным JavaScript
  интерпретатором. CAD API при проверке ввода заменён. Civil 3D не запускался.
  В частности, поведение `vl-sort` с равными ключами этот интерпретатор
  полностью не воспроизводит: вывод о нативной группировке по этим тестам ограничен.

Ветка `claude/autocad-knowledge-hyVpn` содержит SV v16; `main` — исходный
README; `claude/design-browser-game-ui-4dI8A` — другой проект интерфейса.
Рабочий код SV 4/5 найден только в `claude/project-status-check-h0n2w`.

На момент первоначального ревью добавлены воспроизведение и документация. Исправления
