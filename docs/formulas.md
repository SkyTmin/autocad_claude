## Картограмма земляных масс

Метод четырёхгранных призм: площадка делится сеткой квадратов, объём считается
по каждому квадрату как площадь, умноженная на среднюю рабочую отметку.

### Соглашение о знаках

**Рабочая отметка** в узле сетки:

```
h = H(проект) − H(факт)
```

| Знак | Что значит | Работы |
|---|---|---|
| `h > 0` | проект выше земли | **насыпь**, грунт досыпают |
| `h < 0` | проект ниже земли | **выемка**, грунт срезают |
| `h = 0` | совпало | линия нулевых работ |

Знак держим единым во всём проекте. Ошибка в знаке даёт зеркальную
картограмму, и снаружи это выглядит правдоподобно — поэтому соглашение
фиксируется явно, а не держится в голове.

**Встречаются обе конвенции, и это не вопрос вкуса — это вопрос, с кем
сверяют ведомость.**

| Конвенция | Формула | Плюс означает |
|---|---|---|
| в формулах ниже | `h = проект − факт` | насыпь |
| **у Шамиля на объектах** | `h = факт − проект` | **выемку** |

Пример со сверки: земля `13,23`, проект `8,00`, подписано `+5,23` — значит
плюс это выемка, срезать пять с лишним метров.

Поэтому в команде `KG` знак — **переключатель**, а не зашитое правило,
и выбранная конвенция печатается в отчёте. Формулы объёмов ниже написаны
для «плюс — насыпь»; при обратной конвенции меняется только знак `h`,
сами формулы те же.

### Целый квадрат

Все четыре угла одного знака — квадрат целиком в выемке либо целиком в насыпи.

```
V = a² · (h₁ + h₂ + h₃ + h₄) / 4
```

`a` — сторона квадрата, `h₁…h₄` — рабочие отметки углов.

**Контрольный пример.** `a = 20 м`, отметки `0,30 / 0,50 / 0,20 / 0,10`:

```
V = 400 · (0,30 + 0,50 + 0,20 + 0,10) / 4 = 400 · 0,275 = 110,000 м³
```

### Линия нулевых работ

Там, где по стороне квадрата знак меняется, отметка проходит через ноль.
Положение нулевой точки — линейная интерполяция, отсчёт **от узла i**:

```
x = a · |hᵢ| / (|hᵢ| + |hⱼ|)
```

Соединяя нулевые точки на сторонах, получаем линию нулевых работ — границу
выемки и насыпи.

### Переходный квадрат: один угол против трёх

Линия отсекает **треугольник** у «одинокого» угла, остаётся **пятиугольник**.

Общее правило для любой фигуры: **объём = площадь × среднее рабочих отметок
её вершин**, причём у вершин на нулевой линии отметка равна нулю.

```
треугольник   (вершины h, 0, 0)          V = S · h / 3
пятиугольник  (вершины h₁, h₂, h₄, 0, 0) V = S · (h₁ + h₂ + h₄) / 5
```

Площадь треугольника — по двум отрезкам от одинокого угла до нулевых точек:

```
S(треуг) = x₁ · x₂ / 2
S(пятиуг) = a² − S(треуг)
```

**Контрольный пример.** `a = 20 м`, обход углов `+0,30 / +0,50 / −0,20 / +0,10`,
одинокий угол — третий:

```
нулевая точка по стороне 3-2:  x = 20 · 0,20 / (0,20 + 0,50) =  5,714 м
нулевая точка по стороне 3-4:  x = 20 · 0,20 / (0,20 + 0,10) = 13,333 м

выемка   S = 5,714 · 13,333 / 2  =  38,095 м²   V = 38,095 · 0,20 / 3 =  2,540 м³
насыпь   S = 400 − 38,095        = 361,905 м²   V = 361,905 · 0,90 / 5 = 65,143 м³

контроль площадей: 38,095 + 361,905 = 400,000 = a²   ✔
```

### Переходный квадрат: два угла против двух

Линия пересекает две **противоположные** стороны, квадрат делится на две
трапеции. У каждой две вершины с рабочими отметками и две нулевые:

```
S = a · (b₁ + b₂) / 2
V = S · (hᵢ + hⱼ) / 4
```

`b₁`, `b₂` — отрезки на разрезанных сторонах, `hᵢ`, `hⱼ` — отметки двух углов
этой трапеции.

### Переходный квадрат: по диагонали

Два противоположных угла в насыпи, два других в выемке. Линия нулевых работ
проходит двумя ветвями, квадрат распадается на четыре части.

**Редкий случай, но обрабатывать обязан:** пропущенный или посчитанный
по общей формуле — это молча неверный объём. Разбиваем квадрат диагональю
на два треугольника и считаем каждый отдельно по правилу «площадь × среднее
вершин».

### Осторожно: формула зависит от ЧИСЛА вершин

Правило «объём = площадь × среднее отметок вершин» считает вершины
**равноправными**. Значит лишняя вершина на прямом участке — не безобидна:
она входит в среднее наравне с настоящими и тянет его к себе. Фигура при этом
не меняется, площадь тоже.

**Контрольный пример.** Трапеция в квадрате 20 м, рельеф с уклоном
`h = 0,05·x + 0,02·y`, вершины `(0,0) (20,0) (20,14) (0,6)`:

```
4 настоящие вершины            S = 200,00 м²  h̄ = 0,6000  V = 120,000 м³
+ 10 лишних на нижней стороне  S = 200,00 м²  h̄ = 0,5286  V = 105,714 м³  −11,9 %
+ 100 лишних                   S = 200,00 м²  h̄ = 0,5038  V = 100,769 м³  −16,0 %
```

Тот же эффект на контрольном треугольнике выше (`V = S·h/3 = 2,540 м³`):
если добавить вершины на нулевой линии, где `h = 0`, объём падает до
`0,254 м³` при 30 вершинах — **в десять раз**.

**Отсюда два правила.**

1. В расчёт идёт контур, **очищенный от коллинеарных вершин**. Это делает
   `gc-kg-clean` сразу после сшивки контура (`docs/pitfalls.md` → П56).
2. **Площадь эту ошибку не ловит** — она не меняется. Контроль площади,
   который печатает команда, здесь бесполезен, и полагаться на него нельзя.
3. Чистка помогает **не всегда**. Краевой квадрат обрезан границей
   поверхности, и её точки идут по кривой — они не коллинеарны, удалять
   их нельзя. Значит для таких фигур меняется сама формула (ниже).

### В среднее идут ПОДПИСАННЫЕ узлы, а не все вершины контура

Правило одно и проверяемое глазами по чертежу:

> **Сколько подписей стоит на квадрате — столько отметок вошло в среднее.
> Площадь при этом берётся настоящая, по всему контуру.**

Контур краевого квадрата описывает **форму края**: между расчётными узлами
он несёт точки границы поверхности. Они задают, где проходит край, но
отметок не несут и подписей не получают — значит и в среднее идти не
должны. Формула считает вершины равноправными, поэтому каждая лишняя
тянет среднее к себе (раздел выше).

```
краевой квадрат со сверки: 8 вершин контура, подписано 4 узла

  по всем 8 вершинам   (2,97+1,62+0+0+0+0+0+0) / 8 x 21,334 = 12,22   ← провал
  по 4 подписанным     (2,96+1,62+0,00+0,00)   / 4 x 21,334 = 24,43   ← образец 24,43
```

Контур по узлам чуть меньше настоящего — край между узлами спрямляется, —
поэтому расчёт возвращается на настоящую площадь множителем `S / S(узлы)`.
Так сумма площадей насыпи и выемки продолжает сходиться с площадью
картограммы.

### Два метода и почему они дают разные числа

Разбор из статьи автора образца, с числами — годится как контрольный пример.

Квадрат 10 × 10 м, рабочие отметки по углам `3,98 / 3,95 / 1,50 / 0,69`.

**По призмам (триангуляция).** Строится объёмное тело по всей геометрии
поверхностей, со всеми ямками и буграми внутри квадрата: **307,4 м³**.
Точнее, но проверить на бумаге нельзя — число выдаёт Civil 3D, и откуда
оно взялось, принимающей стороне не показать.

**По квадратам.** В расчёт идут только отметки в вершинах:

```
S   = 10,0 × 10,0 = 100,0 м²
Hср = (3,98 + 3,95 + 1,50 + 0,69) / 4 = 2,53 м
V   = 100,0 × 2,53 = 253,0 м³        (в статье 250,3 — опечатка либо иное округление)
```

Разница с 307,4 м³ велика, потому что метод не видит перелома рельефа
внутри квадрата. Зато любой проверяющий пересчитает его на калькуляторе.

**По квадратам, с разбивкой по характерной линии перелома.** Квадрат
режется линией перелома на две фигуры, и каждая считается отдельно:

```
S1 = (4,1 + 5,8) / 2 × 10,0 = 49,5 м²   Hср1 = (3,98+3,95+3,86+3,72)/4 = 3,87 м
S2 = (5,9 + 4,2) / 2 × 10,0 = 50,5 м²   Hср2 = (3,72+3,90+1,50+0,69)/4 = 2,45 м

V1 = 49,5 × 3,87 = 191,6 м³
V2 = 50,5 × 2,45 = 123,7 м³
V  = 315,3 м³
```

Уже близко к 307,4 м³ и по-прежнему проверяется руками. **Это и есть
смысл характерных линий**: они не оформление, а способ поднять точность
метода квадратов, не теряя проверяемости.

> У нас разбивка по характерным линиям **пока не сделана** — линии
> выбираются в окне, но в расчёт не идут (`status/ISSUES.md` → #006).

### Какие точки контура считаются расчётными узлами

Вершина контура идёт в среднее, если выполнено одно из двух:

1. **это узел сетки** — кратны шагу **обе** координаты;
2. **отклонение вершины от хорды между соседями не меньше 0,23 м**.

Точка, у которой кратна только одна координата, узлом **не является**:
граница может задеть линию сетки по касательной и уйти обратно. Настоящее
пересечение распознаётся само — контур в нём поворачивает вдоль стороны
квадрата, и излом выходит большой.

**Откуда 0,25 м.** Порог снят с образца сверкой наборов узлов (`KGC`).
Десять вершин с известным ответом:

```
вершина      излом    откл.   образец
i=6 j=5 в3   18,0°    0,321     ДА
i=6 j=1 в2   19,3°    0,258     ДА
i=1 j=6 в2   27,0°    0,294     ДА
...          22,3°    0,137     нет
i=3 j=7 в2   10,5°    0,219     нет
i=7 j=1 в2   16,3°    0,059     нет
i=2 j=0 в5    4,0°    0,045     нет
i=6 j=1 в3   11,0°    0,035     нет
i=2 j=0 в6    1,3°    0,018     нет
i=6 j=5 в2    2,8°    0,007     нет
```

**Угол не годится**: вершину с изломом 22,3° образец не подписал, а с 22,8°
подписал — разделить их углом нельзя ни при каком пороге. По отклонению
вилка `(0,219 ; 0,244]` на двенадцати вершинах, взято 0,23 — середина.

И по смыслу отклонение правильнее: угол не знает длины звена. Излом 22°
на коротком звене — шум оцифровки, он и отклонения почти не даёт.

> Порог снят при шаге сетки 5 м. Абсолютный он или долевой от шага — по
> одному шагу не различить. И возможно, у образца порог круглые 0,25, но
> отклонение мерится от хорды между **оставленными** после упрощения
> вершинами — упрощением всей границы, а не вершина за вершиной
> (`docs/pitfalls.md` → П79).

### Рабочая отметка считается от ОКРУГЛЁННЫХ отметок

```
h = round(H проектная, n) − round(H существующая, n)
```

`n` — та же точность, с какой отметки печатаются в подписи.

**Зачем.** Чертёж пересчитывают на бумаге. Кто видит в подписи `6,38` и
`3,42`, тот ждёт в рабочей `2,96`. Вычитание точных `6,385 − 3,419 = 2,966`
даёт `+2,97`, и проверяющий видит ошибку, которой нет.

```
образец:  6,38  − 3,42  = 2,96
точное:   6,385 − 3,419 = 2,966  →  +2,97   ← в подписи не сходится
```

Округление берётся тем же `rtos`, которым идёт печать: своя арифметика
`fix(x+0,5)` разошлась бы с ним на ровной половине (`6,385` → `6,39`
против `6,38`), и подпись опять перестала бы сходиться с расчётом.

**Что печатаем — то и вычитаем.** Величина в подписи и величина в расчёте
обязаны быть одним и тем же числом.

**Контрольный пример — краевой квадрат со сверки, 8 вершин**, из которых
шесть идут подряд по границе поверхности с рабочей отметкой около нуля
(`+2,966 / +1,621 / −0,005 / 0 / 0 / 0 / 0 / +0,001`, площадь 21,334 м²):

```
простое среднее вершин          h̄ = 0,5729   V = 12,22 м³   ← провал
веер из каждой вершины по кругу              V = 23,20…25,65 м³
среднее по веерам                            V = 24,38 м³
плоскость наименьших квадратов               V = 24,59 м³
эталонный инструмент                         V = 24,43 м³
```

Простое среднее — единственный выброс, и он ровно вдвое ниже. Шесть нулей
входят в среднее наравне с двумя настоящими углами.

### Сколько частей даёт нулевая линия

Отсечение целого контура нулевой линией даёт **две** части, пока знак
рабочей отметки меняется при обходе не более двух раз. Четыре смены —
это «переходный квадрат по диагонали» выше: частей четыре, и такой квадрат
режется на треугольники, каждый со своей нулевой линией.

Вершина с нулевой отметкой знака не имеет и в счёт смен не идёт. Но она
попадает в **обе** части сразу — и если таких вершин подряд несколько,
они образуют настоящий многоугольник, площадь которого будет посчитана
дважды. Поэтому часть, в которой нет ни одной вершины своего знака,
отбрасывается целиком: объём её нулевой, а площадь уже учтена в соседней
(`docs/pitfalls.md` → П67).

### Насколько метод точен

Правило «площадь × среднее отметок вершин» **точно** для треугольника и для
целого квадрата, и **приближённо** для фигур с бо́льшим числом вершин —
то есть ровно для тех, что получаются при разрезе переходного квадрата.

Проверено на линейном рельефе, где точное значение считается интегралом:

```
фигура            вершин   по методике    точно      разница
треугольник          3       34,6667      34,6667      0        (точно)
четырёхугольник      4       66,8800      67,3067      0,63 %
пятиугольник         5       66,7670      66,6000      0,25 %
```

На реальной сетке 12×12 по 5 м с рельефом, меняющим знак посреди площадки:

```
объём по ячейкам, алгебраически   −360,208 м³
интеграл аналитически             −360,000 м³
расхождение                          0,208 м³  — 0,004 % от суммы модулей
```

**Контроль площадей при этом идеален**: сумма частей одного знака равна
площади фигуры до машинного нуля — проверено на 300 многоугольниках
произвольной формы.

**Что из этого следует.** Расхождение с чужой ведомостью в сотых долях
процента — не ошибка, а разница методов. У эталонного инструмента их три:
«метод квадратов» (наш), «метод триангуляции (стандартный)» и
«альтернативный» — последние два режут фигуру на треугольники, где формула
точна, и отличаются выбором диагонали. Для квадрата с отметками
`+0,30 / +0,50 / −0,20 / +0,10` одна диагональ даёт 53,33 м³, другая
86,67 м³, а метод квадратов — 70,00 м³, ровно среднее между ними.

Сравнивая объёмы с чужим расчётом, **сначала сверьте метод**, а потом уже
ищите ошибку в числах.

### Сверка с эталонным инструментом (2026-09-07)

Один и тот же квадрат, отметки `+6,85 +6,64 +5,48 +7,50`, шаг сетки 5 м:

```
метод квадратов        эталон 165,44    мы 165,31    разница 0,08 %
наши две диагонали             —        170,08 / 160,79
«триангуляция» эталона 173,49            —
```

**Метод квадратов совпадает.** 0,08 % - это округление отметок на сотых
(у эталона 6,85, у нас 6,84), а не разница в расчёте. По всей площадке
метод в метод: 3820,82 против 3773,54, то есть **1,2 %**, и вся она на
краевых столбцах - средние совпадают до 0,03 %:

```
столбец      1      2      3      4      5      6      7      8
разница  -12,1%  -3,2%  -2,1%  -0,3%  +0,03% +0,04%  -1,9%  -26,9%
```

**Наш «метод триангуляции» - не то же, что у эталона.** Мы делим квадрат
на два треугольника по тем же четырём углам: диагонали дают 170,08 и
160,79, а их среднее и есть метод квадратов 165,44. Эталон даёт 173,49 -
**больше обеих**, а значит из четырёх углов такое не выводится вовсе.
Он считает по рельефу **внутри** квадрата, через поверхность объёмов
Civil 3D.

Поэтому наши методы названы «по треугольникам квадрата, диагональ 1-3 /
2-4», а не «триангуляция»: обещать совпадение, которого способ дать не
может, нельзя.

**Для сверки с эталоном берите метод квадратов.**

### Разведка по файлам эталона (2026-09-08): читать нечего

Вопрос «а не проще ли посмотреть, как считает эталонный инструмент»
закрыт: **его математика из файлов не извлекается**, и повторять эту
работу не нужно.

| что лежит | читается ли |
|---|---|
| девять `*.arx` (C++, релиз без символов) | декомпилируются в «суп» без имён и формул |
| два `*.VLX` (компилированный AutoLISP, FAS, сжатый) | в исходник не разворачивается вовсе |
| один `*.dll` (.NET) | читается, но там только объёмы Civil 3D, расчёта картограммы нет |

Разбор точки входа показал, что `.arx` — это **движок геометрических
примитивов** для LISP: девять функций регистрируются через `acedDefun`,
принимают аргументы и возвращают списки. Сама оркестровка (сетка →
разрез нулевой линией → площадь × среднее → пороги → подписи) лежит
в FAS. Это установлено разбором тел функций, а не предположением.

**Что разведка всё же дала - два независимых подтверждения тому,
что мы вывели из чисел:**

1. В `.arx` вызывается `boost::geometry::centroid` для ЧАСТЕЙ фигуры.
   Значит подпись объёма ставится в центре тяжести части, а не квадрата,
   и на переходный квадрат подписей две (`docs/pitfalls.md` → П86).
2. Деление многоугольника идёт через **Boost.Geometry overlay**, а точки
   пересечения рёбер - через `AcGeCurveCurveInt2d`. Значит эталон режет
   **настоящий контур**, а не хорды между расчётными узлами
   (`status/ISSUES.md` → #009).

**Порога отбора узлов ~0,22 м среди зашитых констант НЕТ.** Зашиты
`1e-6`, `1e-4`, `5e-4`, `1e-3`, `0.05`, `0.1`, `0.25`. Ни `0,219`,
ни `0,244` там тоже нет, то есть порог вычисляется, а не хранится
числом. Вариант «5 % от шага сетки» даёт при шаге 5 м ровно `0,25` -
и он опровергнут данными: вилка, снятая с двух чертежей, (0,219 ; 0,222].

**Ложный след, за которым не надо идти.** В `.arx` нашлись числа
`17.336`, `19.219`, `20.200`, `21.204`, `22.208`, `24.216`, и их приняли
за контрольные примеры автора. Это не они: числа идут почти
арифметической прогрессией с шагом ≈1,004, а сопоставление
«24.216 ↔ наши 24,43» просто неверно - величины разные. Совпадение
`17.336` с нашим тогдашним `17.335` - случайность на трёх знаках среди
тысяч констант в мегабайтном бинарнике. Мерить согласие по числу,
выбранному из-за того, что оно похоже на наше, нельзя
(`docs/pitfalls.md` → П72).

**Практический вывод.** Правила расчёта добываются только сверкой чисел
на живых чертежах. Этим способом за одну сессию найдены и подтверждены
П84-П87; он работает, и другого нет.

**Три метода реализованы** (`kg.lsp` v46, окно «Вычисление»):

| метод | контрольный квадрат, алгебраически | на линейном рельефе |
|---|---|---|
| квадратов, `V = Hср·S` | 62,60 м³ | ошибка 0,208 м³ на 3600 м² |
| триангуляции стандартный | 53,33 м³ | **точно** (6·10⁻¹⁴) |
| триангуляции альтернативный | 86,67 м³ | **точно** (6·10⁻¹⁴) |

Метод квадратов воспроизводит контрольный пример выше в точности:
выемка 2,540 м³, насыпь 65,143 м³.

**Где методы расходятся сильнее всего.** Не на целых квадратах - там у
фигуры ровно четыре вершины, и «среднее вершин» совпадает с точным
значением до нуля. Расходятся они на **краевых фигурах**: у них вершин
десятки (ломаная границы), и все лежат у самого края.

```
вершин у краевой фигуры    по среднему    точно     отклонение
        4                    44,3119     44,0532      0,59 %
       10                    46,6031     45,9408      1,44 %
       40                    47,0782     46,1674      1,97 %
       80                    47,1324     46,1771      2,07 %
целый квадрат (4 вершины)    77,9688     77,9687      0,00 %
```

Знак отклонения зависит от формы рельефа - метод может как завышать, так
и занижать. Поэтому **сверять чужую ведомость надо по краевым столбцам**:
в середине площадки методы дают почти одно и то же, а разница копится
по краю.

**Важная тонкость триангуляции.** Разрезав треугольник нулевой линией,
одна из частей становится четырёхугольником — и считать её по «среднему
вершин» уже нельзя, там формула приближённа. Части надо разбивать на
треугольники и складывать. Без этого триангуляция ошибалась на 0,36 м³
там, где обязана быть точной.

### Итоги и баланс

```
V(выемка) = Σ по всем частям с h < 0
V(насыпь) = Σ по всем частям с h > 0
баланс    = V(насыпь) − V(выемка)
```

Относительный дисбаланс, для оценки «сошлось или нет»:

```
δ = |V(насыпь) − V(выемка)| / ((V(насыпь) + V(выемка)) / 2) · 100 %
```

**Про разрыхление.** Срезанный грунт в насыпи занимает больше места, чем
занимал в целике. Коэффициент остаточного разрыхления `K` (обычно `1,02…1,06`)
задаёт проектировщик, и он **не наш**: мы выдаём геометрические объёмы,
а поправку применяет тот, кто её назначил. Если понадобится — вводим
отдельным параметром, но по умолчанию не трогаем.

### Проектная отметка при нулевом балансе

Если площадка планируется «в ноль», средняя проектная отметка считается
с весами по числу квадратов, которым принадлежит узел:

```
H₀ = (ΣH₁ + 2·ΣH₂ + 3·ΣH₃ + 4·ΣH₄) / (4n)
```

| Обозначение | Какие узлы |
|---|---|
| `ΣH₁` | входят в **1** квадрат — углы площадки |
| `ΣH₂` | входят в **2** квадрата — узлы по краю |
| `ΣH₃` | входят в **3** квадрата — во внутренних углах непрямоугольной площадки |
| `ΣH₄` | входят в **4** квадрата — внутренние узлы |
| `n` | число квадратов |

**Контрольный пример.** Сетка 2×2 квадрата, 9 узлов, отметки:

```
10,20  10,35  10,50
10,10  10,28  10,44
10,05  10,18  10,30

ΣH₁ = 10,20 + 10,50 + 10,05 + 10,30 = 41,05   (четыре угла)
ΣH₂ = 10,35 + 10,10 + 10,44 + 10,18 = 41,07   (четыре узла по краям)
ΣH₃ = 0
ΣH₄ = 10,28                                    (центральный узел)
n   = 4

H₀ = (41,05 + 2·41,07 + 4·10,28) / 16 = 10,2694 м
```

### Что проверять при отладке

1. **Сумма площадей частей квадрата = `a²`.** Первая проверка на любую ошибку
   в геометрии разреза.
2. **Знак.** Насыпь и выемка не перепутаны — проверяется на одном узле руками.
3. **Целый квадрат, посчитанный как переходный при нулевой отметке в углу**,
   должен дать тот же объём, что и по общей формуле.
4. **Диагональный случай не пропущен** — отдельный тест.
5. Итог сверить с эталонным расчётом на том же участке.
