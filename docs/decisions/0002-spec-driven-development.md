# ADR-0002: Spec-Driven Development как обязательный процесс

**Статус**: Принято
**Дата**: 2026-05-03

## Контекст

Проект ведётся преимущественно AI-сессиями. Без жёсткого процесса AI склонна к:
- Тихому упрощению задач
- Placeholder-коду
- Поверхностным фиксам
- Выбору "лёгкого пути" без обоснования

Это деградирует проект. Нужен процесс, который превращает дисциплину из
"обещания" в "артефакт".

## Решение

Принимаем **Spec-Driven Development (SDD)** как обязательный процесс:

1. Спецификация в `specs/NNN-feature.md` пишется **до** кода.
2. Архитектурные решения фиксируются в ADR (`docs/decisions/`).
3. Каждая задача проходит **Definition of Ready** перед стартом и
   **Definition of Done** перед закрытием (см. `CLAUDE.md`).
4. Самопроверка DoD выводится явно в чат **перед каждым коммитом**.
5. Передача между сессиями — через `status/HANDOFF.md`.

Hard Rules (`CLAUDE.md` §3) — операционализация SDD на уровне действий AI.

## Альтернативы

1. **Свободный workflow без процесса** — отвергнуто. AI без жёстких рамок
   деградирует качество, как описано в контексте.
2. **TDD (test-driven)** — недостаточно. Тесты в среде Civil 3D трудно
   автоматизировать; кроме того, тесты ловят баги, но не архитектурный
   дрейф или тихое упрощение scope.
3. **Только чеклист без спек** — отвергнуто. Без письменной спеки задача
   расплывается, AI домысливает требования.

## Последствия

**Положительные**:
- Любая нейросеть может поднять проект с полу-слова через CLAUDE → HANDOFF → ROADMAP
- Решения трассируются, не повторяем дискуссию каждую сессию
- Дисциплина видна в артефактах (спеки, ADR, чеклисты), не в обещаниях

**Отрицательные / риски**:
- Накладные расходы: маленькую правку всё равно нужно немного оформить
  (для тривиальных правок ≤5 строк сделано исключение)
- Если артефакты устаревают и не обновляются — процесс становится фарсом;
  поэтому DoD требует обновления `HANDOFF.md` и `PROGRESS.md`

**Отзывность**: высокая. Если процесс окажется избыточным — его можно
ослабить новым ADR.

## Критерии пересмотра

Пересмотреть, если:
- За месяц 3+ задач закрыты без обновления HANDOFF (значит, процесс не работает)
- Накладные расходы по ощущениям Шамиля превышают пользу
- Появится более совершенная методология, доказавшая себя
