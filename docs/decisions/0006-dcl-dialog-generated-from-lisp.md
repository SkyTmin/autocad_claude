# ADR-0006: Диалоговое окно на DCL, генерируемое самим `.lsp`

**Статус**: Принято
**Дата**: 2026-09-01

## Контекст

Все команды проекта до сих пор управлялись из командной строки: кнопки
`initget`, вложенные запросы, текстовое меню по `Enter`. Для команд с двумя-тремя
настройками это работает и работает хорошо — правила выведены в
[`docs/pitfalls.md` → П23](../pitfalls.md#п23--кнопки-накопленные-по-одной-превращаются-в-кашу).

Картограмма другая. У неё около тридцати параметров: две поверхности, шаг
сетки по двум осям, угол, базовая точка, три вида границ, стиль и высота
текста, точность, шесть цветов, порог объёма, девять слоёв. Провести это
через командную строку невозможно: пользователь потеряется на пятом вопросе
и не увидит, что он уже задал, а что нет.

Требование Шамиля прямое:

> «мне нравится, что когда нажимаешь на кнопку, выходит полноценное окно:
> выбрать поверхность нижнюю, верхнюю, и всё в этом духе. Я боюсь, что
> у нас будет вообще непонятно для обычного обывателя»

Опасение справедливое. Тридцать параметров в командной строке — это и есть
«непонятно для обывателя».

### Чем это конфликтует

[ADR-0003](0003-standalone-command-files.md): каждый файл в `commands/`
самодостаточен, потому что загрузка идёт вручную через `APPLOAD`, и внешние
зависимости делают порядок загрузки значимым. Диалог на DCL — это второй
файл рядом с `.lsp`, который надо найти, положить и не потерять.

## Решение

**Интерфейс — диалоговое окно на DCL. Текст диалога хранится внутри `.lsp`
и записывается во временный файл при открытии.**

```lisp
;; при открытии диалога
1. собрать текст DCL из строк, лежащих в самом .lsp
2. записать во временный файл
3. (load_dialog путь) → (new_dialog "gc_kg" id)
4. работа с окном
5. (unload_dialog id), временный файл удалить
```

Почему так, а не отдельный `.dcl` рядом:

1. **ADR-0003 сохранён.** Распространяется по-прежнему **один файл**. Шамиль
   кидает `.lsp` коллеге, тот делает `APPLOAD` — и всё работает. Потерять
   половину комплекта невозможно.
2. **Нет поиска пути.** Не нужно ни `findfile`, ни настройки путей поиска,
   ни вопросов «а куда положить второй файл».
3. **Кодировка одна.** `.lsp` в CP1251
   ([ADR-0004](0004-lisp-files-cp1251.md)), строки из него пишутся в файл
   как есть, DCL читается в той же ANSI. Русские подписи не превращаются
   в кашу — второй файл со своей кодировкой был бы новым источником
   [П10](../pitfalls.md#п10--кодировка-lsp--cp1251-не-utf-8).
4. **Правится в одном месте.** Диалог и код, который его читает, лежат рядом
   и не разъезжаются.

Цена решения — текст DCL живёт в LISP-строках, и его чуть менее удобно
редактировать. Приемлемо: диалог пишется один раз, а собирается из отдельных
блоков по разделам, а не одной простынёй.

### Почему DCL, а не .NET-палитра

- DCL работает в **чистом AutoLISP**, без сборки, без `NETLOAD`, без
  зависимости от версии Civil 3D и от того, установлен ли .NET-модуль.
  Это то же соображение, что и в [П6](../pitfalls.md#п6--visual-lisp-com-может-быть-недоступен):
  чем меньше слоёв, тем меньше мест, где не заработает у коллеги.
- Диалог на .NET требует собрать `.dll` под конкретную версию, положить её,
  сделать `NETLOAD` и следить за совместимостью при обновлении CAD.
- DCL некрасив по нынешним меркам, но предсказуем и живёт двадцать лет.

### Правила из П23 остаются в силе

Диалог не отменяет их, а переносит в другую форму:

| Правило командной строки | Как в диалоге |
|---|---|
| Один главный режим, остальное подчинено | Неприменимые поля **гасятся** (`mode_tile ... 1`), а не молчат |
| Никаких слепых переключателей | Всё видно на экране: значение написано рядом с полем |
| Enter говорит вслух, что осталось | `Отмена` не меняет ничего, `ОК` печатает в консоль, что принято |

Дополнительно: **проверка при `ОК`**. Ошибочное значение не закрывает окно,
а подсвечивает строку ошибки внутри диалога — пользователь не теряет
введённое.

## Альтернативы

**Оставить командную строку.** Отклонено: тридцать параметров через `initget`
нечитаемы, а Шамиль прямо просил окно.

**Отдельный `.dcl` рядом с `.lsp`.** Отклонено: ломает ADR-0003, добавляет
поиск пути и второй файл, который теряется при передаче.

**Палитра на .NET.** Отклонено: сборка под версию, `NETLOAD`, новая точка
отказа у коллег. Может пригодиться, если DCL упрётся в свои ограничения.

## Последствия

Хорошее:

- один файл на команду, как и было;
- всё видно на экране разом — то, чего просил Шамиль;
- работает без .NET и без внешних файлов.

Плохое и принятое сознательно:

- текст DCL внутри LISP-строк редактировать менее удобно;
- DCL не умеет современных элементов: нет вкладок, деревьев, превью.
  Разделы разносим рамками и колонками;
- временный файл создаётся при каждом открытии окна — удаляем за собой.

Командам с двумя-тремя настройками (`OL`, `VO`, `SV`, `VID`, `RS`) диалог
**не нужен**: там командная строка удобнее и быстрее. Это решение только
для команд с большим числом параметров.

## Порядок работ: сначала функционал, потом внешний вид

Решение Шамиля, зафиксировано отдельно, потому что определяет очерёдность:

> «сначала сделаем чтобы функционал работал как надо, а потом наведём
> красоту, даже если придётся двумя файлами работать или даже тремя»

Из этого следует:

1. **DCL — это временное решение, и это признано сразу.** Он не «навсегда»,
   он «на время, пока считаем». Значит вкладываться в вылизывание окна
   на DCL не нужно: достаточно, чтобы всё было на месте и понятно.
2. **Ограничение «один файл» перестаёт быть железным.** ADR-0003 писался
   исходя из того, что комплект из нескольких файлов теряется при передаче.
   Шамиль согласен на два-три файла ради нормального интерфейса — значит
   при переходе на .NET это не будет нарушением, а осознанной ценой.
3. **Код нужно писать так, чтобы интерфейс отделялся.** Расчёт не должен
   знать, откуда взялись настройки: из DCL, из палитры или из файла.
   Настройки собираются в один список и передаются дальше — заменить
   источник тогда можно, не трогая математику.

Пункт 3 — то, что реально экономит время потом. Он выполняется с самого
начала: `gc-kg-cfg` это простой список пар, окно лишь заполняет его.

## Критерии пересмотра

- Функционал доведён до конца — вернуться к вопросу о внешнем виде,
  и тогда .NET-палитра рассматривается всерьёз (см. раздел выше).
- DCL упёрся в ограничения раньше этого срока — обсудить досрочно.
- Временный файл не создаётся из-за прав доступа — переходить на файл рядом
  с `.lsp` с поиском через `findfile`.
