# ADR-0003: Каждый командный файл самодостаточен

**Статус**: Принято
**Дата**: 2026-07-29

## Контекст

К третьей команде (`SV`/`SVP`, `VID`, `VO`) появились хелперы, нужные больше
чем одному файлу:

- разбор размера/отметки из строки вида `4,398` (запятая как разделитель);
- обратное форматирование числа в `4,398`;
- извлечение координат и высоты из объекта (COGO Point, `POINT`, `CIRCLE`, …);
- выбор текстового стиля с fallback `GOSTB` → `ISOCPEUR` → `Standard`;
- создание слоя, если его нет.

В проекте есть папка `src/lisp/lib/` — напрашивается вынести общее туда.

Ограничение: файлы загружает Шамиль вручную через `APPLOAD`. Он не программист.
Если `vo.lsp` начнёт зависеть от `lib/geometry.lsp`, то:

- порядок загрузки становится значимым — забыл библиотеку, получил
  «no function definition» посреди работы;
- `(load "lib/…")` внутри файла завязывается на путь, а `APPLOAD` не задаёт
  рабочую директорию предсказуемо;
- перенос одного файла на другой компьютер перестаёт работать.

## Решение

**Каждый файл в `src/lisp/commands/` загружается независимо и не требует
других файлов проекта.** Общие по смыслу хелперы дублируются в каждом файле
с собственным префиксом команды: `gc-pile-*` в `sv.lsp`, `gc-vid-*` в
`vid.lsp`, `gc-vo-*` в `vo.lsp`.

`src/lisp/lib/` остаётся для будущего кода, который **не** грузится через
`APPLOAD` напрямую (например, если появится `acaddoc.lsp` с управляемым
порядком загрузки).

Префикс обязателен: он же защищает от коллизий имён, когда два файла проекта
загружены одновременно.

## Альтернативы

1. **Общая библиотека в `src/lisp/lib/` + `(load …)` из каждой команды.**
   Отклонено: ломает «скопировал один файл — работает», а цена ошибки ложится
   на Шамиля посреди работы в чертеже.
2. **Один монолитный файл со всеми командами.** Отклонено: `sv.lsp` уже 770
   строк; сложение всех команд в один файл делает правки рискованными и
   мешает грузить только нужное.
3. **`acaddoc.lsp` с автозагрузкой всего набора.** Отложено: потребует
   настройки путей на машине Шамиля. Вернёмся, когда команд станет много —
   тогда эта ADR будет заменена.

## Последствия

Плюсы:

- любой файл из `commands/` работает сам по себе, порядок загрузки не важен;
- команду можно отдать/скопировать одним файлом;
- правка одной команды не может сломать другую.

Минусы:

- дублирование ~40 строк хелперов на файл;
- **исправление бага в дублированном хелпере нужно применять во всех файлах,
  где он есть.** Митигация: одинаковые хелперы называются одинаково с точностью
  до префикса (`gc-vid-parse-size` ↔ `gc-vo-parse-num`), в шапке файла
  указано, что хелперы дублированы осознанно по этой ADR.

Пересмотреть, когда: появится `acaddoc.lsp` или число команд превысит ~6.
