# ADR-0004: Файлы `.lsp` хранятся в CP1251

**Статус**: Принято
**Дата**: 2026-07-29

## Контекст

Шамиль открыл проект на втором компьютере и увидел в командной строке кашу:

```
РљРѕРѕРїРёРєСѓ ...  Enter вЂ ...
```

Это классический мохибейк: `Рљ` — это байты `D0 9A`, то есть буква `К`
в UTF-8, прочитанные как CP1251. Файлы `.lsp` лежали в UTF-8 без BOM,
а AutoCAD на том компьютере читает `.lsp` в системной ANSI-кодировке
(на русской Windows это CP1251).

На первом компьютере те же файлы отображались правильно — значит там
AutoCAD новее и распознаёт UTF-8 сам.

Проект уже наступал на это: коммит `eeb1152 fix(sv.lsp v5): CP1251 encoding`
и следом `e4f70d0 ... revert to UTF-8`. Причина отката не зафиксирована,
поэтому решение принимается заново и документируется.

Важно: это **не** та же проблема, что «кириллица в `initget`» (правило 1
в `status/HANDOFF.md`). Там ломался разбор ключевых слов, здесь — отображение
любых русских строк.

## Решение

**Файлы `src/lisp/commands/*.lsp` хранятся в кодировке CP1251 (windows-1251),
без BOM.**

Почему это работает на обоих компьютерах:

- Старый AutoCAD читает `.lsp` в системной ANSI — то есть в CP1251 → верно.
- Новый AutoCAD пробует UTF-8, а байты CP1251 в кириллическом диапазоне
  не образуют валидный UTF-8 → откат на ANSI → тоже верно.

UTF-8 без BOM работает только на новых версиях, UTF-8 с BOM — тоже только
на новых. CP1251 — единственный вариант, покрывающий обе.

Символы, которых нет в CP1251, в коде запрещены. При конвертации заменены
два: `≥` → `>=` и `×` → `x`. Оба были в комментариях.

Документация (`*.md`) остаётся в UTF-8 — её читают люди и GitHub, а не AutoCAD.

## Альтернативы

1. **UTF-8 с BOM.** Отклонено: старый AutoCAD всё равно прочитает как ANSI,
   а BOM добавит мусор в начало файла.
2. **`.gitattributes` с `working-tree-encoding=windows-1251`.** Отклонено:
   в репозитории файл остался бы UTF-8, но при скачивании ZIP-архивом
   с GitHub атрибут не применяется — Шамиль получил бы UTF-8 и ту же кашу.
   Нужны реальные байты CP1251 в репозитории.
3. **Только латиница в сообщениях пользователю.** Отклонено: интерфейс
   должен быть русским, это требование `CLAUDE.md` §5.
4. **Экранирование `\U+XXXX`.** Отклонено: в `princ` не разворачивается,
   работает только внутри текстовых объектов чертежа.

## Последствия

Плюсы:

- файлы работают в AutoCAD любой версии на русской Windows;
- ничего не нужно настраивать вручную.

Минусы:

- **GitHub показывает `.lsp` в вебе как кашу** — он предполагает UTF-8.
  Это ожидаемо и не является поломкой. Смотреть код лучше локально
  в редакторе с выбором кодировки.
- `git diff` по этим файлам менее читаем.
- **При правке `.lsp` любым инструментом надо следить за кодировкой.**
  Редактор, сохранивший файл в UTF-8, вернёт баг. Проверка:
  `file -b --mime-encoding src/lisp/commands/*.lsp` не должно давать `utf-8`.

Пересмотреть, когда: у Шамиля не останется компьютеров со старым AutoCAD.
