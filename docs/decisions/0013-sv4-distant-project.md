# ADR-0013: Сопоставление далёкого проекта в SV 4

**Дата**: 2026-11-02. **Статус**: принято при исправлении issue #011.

## Контекст

Унаследованный от SV 3 радиус поиска 2 м от центра среза отсекает проект
при большом продлении наклонной сваи. При 1:4,5 и перепаде 10 м центр
смещается на 2,222 м. Отметка -10 допустима; терять белое отклонение нельзя.

## Решение

В SV 4 оставляем автоматическое сопоставление ближайшего свободного
проекта в пределах 2 м. Если кандидата нет и исходная выборка содержит
ровно одну пару сечений и один проект, сопоставляем их без предела.
Иначе пользователь указывает свободный проект из исходной выборки.
Промах повторяет запрос, Enter пропускает только текущее белое отклонение,
не расходуя проект. Круги, эллипсы и точки обрабатываются прежним способом.

Однозначность определяется по исходной выборке: последний оставшийся
проект в пакетном запуске не становится автоматически однозначным.
Выбранный центр удаляется из списка ровно один раз. Слои, цвет 7,
полные миллиметры и расположение белых подписей остаются как в SV 3.
Общий старый обработчик SV 3 / SVP и его предел не меняются.

## Альтернативы и ограничения

Неограниченный ближайший сосед и простое увеличение постоянного радиуса
могут связать срез с чужой сваей в группе. Сопоставление по нижнему центру
тоже не универсально: проект может быть задан на другом уровне.
Явный выбор нужен только при отсутствии близкого кандидата. Существующий
выбор ближайшего внутри 2 м сохраняется; глобальное сопоставление всей
группы свай это исправление не решает.

## Проверка

Регрессия Z=-10 воспроизводила отсутствие белого отклонения до правки,
после проходит. Проверены выбор дальнего проекта, отказ чужого и уже
использованного центра, Enter без расходования, промах, пакетный запуск,
ближний поиск и неизменность SV 3 / SVP. В Civil 3D проверяет пользователь.
