# ADR-0008: Свой модуль .NET — необязательный, собирается одним файлом

**Статус**: Принято
**Дата**: 2026-09-03
**Уточняет**: [ADR-0001](0001-hybrid-autolisp-dotnet.md), [ADR-0003](0003-standalone-command-files.md)

## Контекст

Сетка картограммы обрезается по краю области, а край — это граница
поверхности. Из чистого AutoLISP её видно только косвенно: опрашиваем
отметки в узлах и по смене ответа ищем край делением пополам. Получается
**ломаная по своим точкам**, а не настоящее ребро триангуляции.

На чертеже это видно: контур не ложится на границу поверхности, идёт
ступеньками с характерным размером в долю квадрата. Шамиль:

> «Почти идеально, но всё же нет»

Уточнение дроблением упирается в предел: сколько ни мельчи, край остаётся
нашим приближением. Совпасть точно можно только одним способом — взять
у Civil 3D саму границу.

В .NET-интерфейсе Civil 3D она отдаётся напрямую. В COM, доступном
из AutoLISP, — нет.

Вопрос Шамиля был прямой:

> «а чё мы не можем сделать свой .dll?»

## Решение

**Можем и делаем. Модуль .NET из одного файла, необязательный,
собирается на машине пользователя без Visual Studio и без SDK.**

```
src/dotnet/GcSurface/
    GcSurface.cs   — исходник, одна функция для LISP
    build.bat      — сборка двойным кликом
```

### Почему это не противоречит прежним решениям

[ADR-0001](0001-hybrid-autolisp-dotnet.md) с самого начала называет проект
гибридом AutoLISP и .NET. Мы просто дошли до задачи, где вторая половина
нужна.

[ADR-0003](0003-standalone-command-files.md) требует, чтобы команда
распространялась одним файлом. Требование сохранено, потому что **модуль
необязателен**:

| Модуль | Что делает `KG` |
|---|---|
| не загружен | работает как раньше: край ищется опросом, приближённо, и команда говорит об этом вслух |
| загружен | берёт границу у поверхности и режет сетку точно |

Проверка одна — есть ли функция среди загруженных. Никаких «нужна версия
такая-то»: нет — работаем хуже, но работаем.

### Почему сборка на машине пользователя, а не готовая `.dll`

1. **Собрать здесь нечем.** В окружении, где пишется код, нет ни Windows,
   ни Civil 3D: ссылки на `AcDbMgd.dll` и `Aecc*Mgd.dll` берутся только
   из установленной программы.
2. **Версии.** Сборка привязана к версии Civil 3D. Одна готовая `.dll`
   не подойдёт всем, а собранная на месте берёт библиотеки той версии,
   которая стоит.
3. **Доверие.** Готовая `.dll` из интернета блокируется Windows и вызывает
   предупреждение `NETLOAD`. Собранная локально — своя.
4. **В репозитории только исходный текст.** Двоичных файлов не держим.

### Почему это выполнимо без Visual Studio

Компилятор C# (`csc.exe`) входит в состав .NET Framework 4, а тот есть
в любой Windows начиная с восьмой. Ставить нечего. `build.bat` находит
компилятор и папку Civil 3D сам и вызывает сборку одной строкой.

Ссылки на `Aec*Mgd.dll` подключаются **все, какие есть в папке**, а не
выбранные по именам: от версии к версии классы переезжают между сборками,
и угадывание, в какой лежит нужный, — гарантированная поломка на чужой
машине. Лишние ссылки компилятору не мешают.

## Альтернативы

**Мельче дробить край.** Отклонено как решение: уменьшает ступеньку, но
не убирает её, а опрос дорожает квадратично. Остаётся запасным путём.

**Всегда требовать границу-полилинию от пользователя.** Отклонено: Шамиль
просил, чтобы область определялась сама. Ручной выбор остаётся как
дополнительное сужение, но не как обязанность.

**Взять готовую чужую `.dll`.** Отклонено. В репозитории должен быть только
наш код, и его происхождение должно быть очевидным.

**Полноценный проект Visual Studio.** Отклонено на этом этапе: требует
установки среды и превращает правку в отдельное умение. Один `.cs` плюс
`.bat` правится блокнотом.

## Последствия

Хорошее:

- контур совпадает с границей поверхности, а не приближает её;
- опрос поверхностей в узлах становится не нужен там, где есть граница —
  считается быстрее;
- открывается путь к тому, чего в COM нет вовсе: поверхность объёмов,
  точные объёмы внутри контура, нулевая горизонталь;
- команда без модуля продолжает работать.

Плохое и принятое сознательно:

- у пользователя появляется шаг «собрать один раз» и `NETLOAD` при каждом
  запуске CAD, пока модуль не прописан в автозагрузку;
- сборка привязана к версии Civil 3D: обновил CAD — пересобери;
- отладить `.cs` без CAD под рукой нельзя. Значит цена ошибки в нём выше,
  чем в LISP: писать только то, что действительно нельзя сделать в LISP,
  и печатать наружу подробности отказа.

## Критерии пересмотра

- Сборка не идёт на машине Шамиля — вернуться к приближённому краю
  и мельчить дробление.
- Модуль перестаёт быть необязательным (`KG` без него не работает) —
  это нарушение ADR-0003, нужен новый ADR.
- Функций в модуле стало больше десятка — заводить нормальный проект.
